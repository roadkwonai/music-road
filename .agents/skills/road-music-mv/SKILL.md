# Road Music 뮤직비디오

음악의 감정과 연출 의도를 실제 관찰 근거, 재현 가능한 샷, 검수한 영상으로 연결한다. 한국어로 보고한다. 감독의 명성이나 모델 이름을 품질 보증으로 쓰지 않는다.

## 제작 기록

실제 MV 제작·수정 요청은 [제작 기록 스킬](../road-music-production-records/SKILL.md)으로 최초 요청과 수정 프롬프트를 남기고, 각 실제 분석·이미지·렌더 작업의 시간·결과 파일을 연결한다. 기획만 한 경우에는 제작 작업 완료 수치나 파일을 기록하지 않는다.

## 프로젝트 저장공간

작업 시작·수정·완료의 저장공간은 [저장공간 운영 스킬](../../../skills/road-music-storage/SKILL.md)을 함께 적용한다. 원음·완성본·승인 자산·편집 소스를 보존하고 프로젝트별 `.roadmusic/cache`와 중간본·상세 이력을 분리한다. 수정 중 히스토리는 기본 보존하며, 실제 제작 잠금을 사용하고 완료 후 안전한 캐시 정리만 수행한다. 기존 자료는 임의 이동·삭제하지 않고 등록된 항목의 보호 사유·미리보기를 확인한다.

MV 실행 폴더는 `input.json`의 `schema_version:1`·`source_audio`/SHA와 `production-plan.json`의 objective/tasks를 가진 상태에서 공개 `storage:register`로 등록한다. 실제 생성 동안 producer PID lease를 잡고 finally에서 자기 token만 해제한다. 재생성 가능한 concat·임시 PNG·분석 중간 파일은 `.roadmusic/cache/<단계>/`에 격리·등록하고 단계 종료에 용량/파일 수를 확인한다. 승인 이미지·원음·애니매틱 master·최종 영상·검수 이력은 cache로 등록하지 않는다. 자세한 제작 중/완료 정리는 저장공간 스킬의 운영 계약을 따른다.

## 범위와 입력

분석, 기획, 이미지 제작, 전체 MV 제작, 부분 수정 중 요청 범위를 선택한다. 스킬·하네스 구축만 요청했다면 실제 이미지·곡·영상을 생성하지 않는다. 기획만 요청했다면 이미지 프롬프트를 포함한 기획 산출물로 끝낸다. 이미 위임한 제작에 같은 승인을 반복해서 요구하지 않는다.

사용자가 범위를 “교체안 정리·스킬 보완까지만”으로 줄이면 해당 작업의 진행 중인 생성을 먼저 중지하고 결과를 보존한다. 문서 정리가 끝나도 이미지/API·영상·렌더를 새로 시작하거나 자동 재개하지 않는다.

- 확정 음원 인계: 별도 음악 작업이 확정한 원본 음원의 실제 절대 `audio` 경로·SHA-256·길이·원문 가사를 받는다. 이 스킬은 음악 제작을 위한 작곡·가사 생성·후보 청취/평가·후보 비교·곡 선정을 하지 않으며, 지정하지 않은 곡을 목록에서 임의 선택하지 않는다. 인계된 확정 음원의 구간·비트·감정 파악과 완성 MV의 소리/영상 동기 재생 검수는 MV 업무다.
- 영상: 사용자 파일 또는 접근 가능한 공식 URL, 분석 범위. 공식/제작자가 공개한 최고 공개본을 먼저 확인하고 2160p급을 우선 확보한다. 정밀 분석용 실제 파일은 `ffprobe`로 인코딩 스트림이 1920×1080 또는 회전된 1080×1920 이상인지 검증한다. 레터박스/필러박스와 활성 영상 영역은 별도 시각 검수로 기록한다. 표기된 4K·업스케일·리인코딩만으로 품질 향상을 주장하지 않으며, 미달 파일은 정밀 게이트 미달의 표본 상태로만 남긴다. URL·크레딧 조사와 원본 확보는 별도 상태다.
- 제작: 인계된 음원의 장르·subgenre/편곡 버전, 영상 형식(아이돌 퍼포먼스/밴드 라이브/솔로 라이브/서사/혼합 등), 화면 look, 실제/가상 공연, 목적·타깃·비율·길이·FPS, 인물·의상·공간, 이미지·영상 후보/시간/저장공간 예산. 상세 cast·세계관이면 group/world Bible을 만든다. 선택값은 기획 데이터이며 앱/모델의 전용 옵션이 아니다. 기획 가정은 적고 진행하되 필수 입력이 없는 단계만 멈춘다.
- 권한: 원곡·가사·인물·참조 이미지의 사용 범위를 보존한다. 공개 시청 가능성과 모델 참조 입력·재배포 허용을 같다고 취급하지 않는다. 법률 판단은 대신 내리지 않는다.

로드뮤직 첫 호출은 프로젝트 AGENTS.md의 필수 문서와 읽기 전용 초기 확인 절차를 따른다. 기존 작업을 보존한다. CLI 업데이트·모델 설치를 영상 요청의 부수 작업으로 실행하지 않는다.

새 AI 영상 생성의 기본 선택은 [harness-spec.json](references/harness-spec.json)의 `generation_defaults`에 있는 **LTX 2.5 Distilled Q8**이다. 실제 외부 명령에는 설치를 확인한 2.5 로컬 팩을 `--model`로 명시하고 `--distilled`를 선택한다. 2.5는 팩 내장 Gemma 4를 사용한다. 모델이 없으면 생성 단계를 미설치로 보고하며 자동 다운로드나 2.3 대체를 하지 않는다. 사용자가 다른 모델을 명시하거나 기존 2.3 실행을 재현하는 경우에는 그 선택과 당시 기록을 보존한다. 상세 실행 경계는 [ltx-roadmusic.md](references/ltx-roadmusic.md)를 따른다.

## 이미지 도구 선택

사용자가 지정한 도구가 기본값보다 우선한다. 새 생성 전에 아래 순서로 선택하고 계획·manifest·계보에 실제 도구를 일치시킨다.

1. `image_gen`을 선택했으면 키 유무와 관계없이 내장 `image_gen`을 사용한다.
2. 그 외에는 `OPENAI_API_KEY` 환경 변수에 비어 있지 않은 값이 있는지 값 자체를 출력하지 않고 확인한다. 있으면 GPT Image 2.5 API(`gpt-image-2.5-sunburst`), 없으면 내장 `image_gen`을 사용한다. 키를 찾으려고 `.envrc`나 토큰 파일을 읽거나 사용자에게 키를 보내 달라고 하지 않는다.
3. API 응답 오류·사용량 제한·안전 필터는 ‘키 없음’과 다르다. 실패/불확실 응답을 먼저 보존·확인하고 자동 재시도나 임의 도구 변경을 하지 않는다. 사용자가 이후 `image_gen`을 선택하면 그 새 선택을 기록하고 진행한다. 선택한 도구 자체가 없으면 미완료 이유를 보고하며 다른 공급자를 추가하지 않는다.

API는 `method/tool:openai-images-api`와 실제 모델을, 내장은 `method/tool:image_gen`과 확인 가능한 반환 정보만 기록한다. 내장 결과를 GPT Image 2.5라고 표시하지 않는다. 재사용 자산의 원래 도구는 보존하고 검수용 문서 보드는 `compose/local-composite`로 구분한다. 선택이 바뀐 새 생성 자산·계획과 downstream 검수는 다시 결속한다.

## 실행 계약

설계 계약은 [harness-spec.json](references/harness-spec.json), 실행 장부는 동봉한 [codex-harness 실행 가이드](../harness/references/runtime-guide.md)를 따른다. 전체 제작은 **음악에 근거한 연출·스토리→키시트 제작/검수→샷 이미지·실제 스토리보드 제작/검수→원곡 애니매틱/검수→LTX proof·샷·편집→최종 검수**다. 분석/기획만 요청했으면 계획과 프롬프트까지, 이미지까지 요청했으면 해당 이미지 검수까지 구체화한다. 전체 제작의 중간 단계를 텍스트 산출물만으로 완료 처리하지 않는다.

1. 새 실행 ID를 정하고 `.harness/work/<run-id>/input.json`에 별도 음악 작업에서 인계한 실제 음원·가사 경로와 SHA-256, 기준일·목표·제약·사용자의 위임 범위를 기록한다. 외부 파일은 이동하지 않고 경로와 지문으로 연결한다. 원문 가사를 바꾸지 않는다.
2. [plan-template.json](assets/plan-template.json)의 `mv-template`을 실행 ID로 바꾸고 범위별 노드·의존성·완료 기준을 확정한다. `inputs`는 존재하는 불변 파일이다. 아직 없는 산출물은 `dependencies`로 연결한다. 단계 시작 시 외부 원본의 SHA-256·PTS와 실제 가로×세로 해상도, 가로/세로 레터박스 여부를 재확인하고, 공식/제작자 최고 공개본 확인 결과도 함께 고정한다.
3. `python3 -B .agents/skills/harness/scripts/run.py --project . init --plan-file <실제계획> --run-id <실행ID>`로 장부를 만든다. 위 실행 가이드에 따라 실제 자식 ID와 최신 패킷을 연결한다. 장부 명령은 에이전트 실행 명령이 아니다.
4. 이미지 제작 전에 [음악 맞춤 미술·실사 촬영 지침](references/music-led-lookdev.md)으로 의상·실제 장소/세트·소품·화보 구도를 조사한다. 실제 확인한 출처와 사진, 선택 이유·탈락 이유·사용 범위를 남기고 곡의 감정/구간별로 필요한 룩만 선정한다. [전체 연출 계약](references/creative-direction.md)에 따라 `direction/production-design.json`에 음악 구간·그룹/연령 선택 이유·미술·공연·카메라·필름룩·VFX/전환/시각 특수효과를 정의하고, story beat를 shot·image plan과 `direction/storyboard.json`에 연결한다. 서사/퍼포먼스/혼합/추상 형식에 맞는 변화와 결말을 설계한다. 상세 cast·세계관이면 Bible도 검사한다. 모든 필요한 이미지에 완성 프롬프트와 참조 순서를 적는다.
5. 이미지 생성·수정의 기본값은 설치된 `gpt-image-api` 스킬과 기존 runner를 통한 **OpenAI Images API GPT Image 2.5**(`gpt-image-2.5-sunburst`)다. 아래 도구 선택 규칙에 따라 API 키가 없거나 사용자가 `image_gen`을 선택하면 설치된 `imagegen` 스킬의 내장 `image_gen`을 사용한다. 실제 요청/비용 위임 범위를 지키고 키는 환경 변수로만 읽으며 출력하지 않는다. 아트디렉터는 검수한 정체성 master를 보존하면서 음악·장소에 맞는 의상 master와 그 의상의 캐릭터시트, 배경의 필요한 시점·소품 키를 먼저 만든다. 의상이 달라지면 새 룩 ID와 시트를 만들고 기존 얼굴을 새로 디자인하지 않는다. `--stage keys` 독립 검수 뒤 검수된 참조로 단일 샷 이미지를 만들고, 이 패널들을 변형 없이 조립한 실제 스토리보드 페이지를 보존한다. 문서 보드의 로컬 배치는 생성 사진을 재제작하는 일이 아니며 `compose`로 기록한다. `--stage storyboard` 검수 후 원곡 위에 패널을 배치한 실제 애니매틱을 만들고 `--stage animatic`을 통과한다. 셋 모두 `validate_preproduction.py --production-design ... --storyboard ... --stage <단계> --require-ready`를 사용하고 상세 cast는 `--bible`, 애니매틱은 `--animatic-review`를 더한다. 전체 제작에서는 실제 이미지·페이지·독립 검수·애니매틱이 준비되기 전 LTX로 넘어가지 않는다. 기존 API의 이미지-only 게이트는 그대로 유지한다.
6. `validate.py --project . --run <실행ID> --complete`와 도메인 품질 게이트를 함께 확인한다. 정적 통과는 실제 역할 로딩·영상 품질의 증거가 아니다.

실제 결과·검사는 `run.py result`로 등록하고 native 유휴 상태도 별도 확인한다. 이미 충족된 자산은 보존·재사용하며, 수정한 입력과 downstream만 재검수한다. 독립 자료에 비중첩 경로를 배정하고 renderer 작업은 한 번에 하나다. 필수 입력·실물·검수 누락 또는 critical/high 결함이 있으면 해당 downstream을 실행하지 않는다.

네이티브 턴의 종료와 제작 노드의 완료를 구분한다. 이미지 생성만 끝나고 보드·manifest가 남았다면 부분 진행을 보존하고 메인이 동일 담당자에게 최신 패킷과 남은 작업만 후속 배정한다. 같은 계약의 후속 턴 때문에 성공한 API를 다시 제출하지 않으며, 산출물·검사가 모두 갖춰진 뒤에만 노드를 완료 등록한다. 입력·소유권·계약이 바뀌면 기존 실행을 보존하고 하네스의 새 실행·재검증 절차를 따른다.

전체 샷 배치 전에는 `create-samples → review-samples`에서 서로 다른 핵심 구도의 실제 대표 샷을 검수한다. 상위 연출안의 shot-size·시선·행동이 실제 샷에 반영됐는지 확인하고, 통과한 표본을 최종 집합에 재사용한다. 표본 pass는 전체 보드 승인과 다르며 세부 기준은 [전체 연출](references/creative-direction.md)을 따른다.

인물 중심 형식에서는 군무를 제외한 자리를 빈 배경으로 채우지 않는다. [공간 컷 검수](references/creative-direction.md#인물-중심-형식의-공간-컷)에 따라 전체·음악 구간별 인물 노출과 빈 공간의 실제 길이·연속 배치를 확인하며, 구조·해시 통과와 연출 적합성 판정을 구분한다.

캐릭터시트의 기본 제출 프롬프트는 사용자가 선택한 [현재 원문](assets/character-sheet.prompt.txt)을 그대로 사용한다. 별도 수정 위임이 없으면 번역·요약·재작성하거나 멤버 이름·스타일을 앞뒤에 붙이지 않는다. 승인된 단일 master를 참조로 전달한다. 왼쪽 얼굴 확대와 얇은 구분선, 위쪽 여백을 둔 중앙 목~발 독립 크롭, 머리 전체가 보이는 오른쪽 후면을 같은 신체 축척·바닥선으로 배치한다. 중앙 머리 제외는 의도된 구도이며 시트를 I2V 시작 이미지로 쓰지 않는다. 사용자가 기존 시트의 특정 구도 오차를 허용하고 계속 진행하라고 지시하면 그 허용 범위를 기록하고 해당 이유만으로 재생성하지 않는다. 인물·의상 일관성과 심각한 신체 오류는 별도로 검수한다.

### 역할과 소유권

| 역할 | 책임 | 배정 경로 |
|---|---|---|
| `mv_reference_analyst` | 근거·전 프레임·샷·전환 분석 | `references/<reference-id>/` |
| `mv_director` | 음악별 전체 연출·그룹/세계관·스토리·샷·스토리보드 계획 | `direction/` |
| `mv_art_director` | 기본 GPT Image 2.5 API/선택된 image_gen 의상·캐릭터·배경·소품·샷 이미지, 실제 스토리보드 페이지·자산 명세 | `visuals/keys/`, `visuals/storyboard/`와 배정 manifest |
| `mv_ltx_producer` | 원곡 애니매틱, 검증한 LTX proof·샷·편집·인코딩 | `preproduction/`, `production/` |
| `mv_quality_reviewer` | 키시트·이미지 스토리보드·애니매틱·최종 영상의 독립 검수 | 작업별 `review/*.json` |

경로는 `.harness/work/<run-id>/` 아래다. 메인이 장부·공유 입력·통합·완료 판정을 소유한다. 두 작성자가 같은 경로에 쓰지 않는다. 새 역할이 현재 도구 목록에 없으면 정의를 읽어 노출된 `researcher`/`vision`/`executor`/`verifier`에 전달하고 대체 사실을 기록한다. 없는 `agent_type`을 발명하지 않는다. 단독 수행의 자기 검토를 독립 검토라고 보고하지 않는다.

## 종료

전 프레임 색인과 실제 검토 범위를 분리한다. `audit_coverage.py --require-complete`와 독립 원본 대조를 통과해야 전수 분석으로 보고한다. 새 원본의 SHA-256 또는 PTS가 달라지면 기존 관찰을 새 원본에 다시 결속하고 재검토한다. 일부만 보거나 원본이 없으면 누락을 표시한다.

음악 생성·가사 작성·음악 제작을 위한 후보 청취/평가·후보 비교·곡 선정은 별도 음악 작업의 범위다. 그 작업이 필요하면 프로젝트 음악 운영 지침과 선택한 엔진별 지침을 별도로 적용하며, 이 MV 스킬의 실행 노드나 승인 게이트로 추가하지 않는다. 이는 YuE2를 포함한 사용자의 실제 엔진 선택을 바꾸지 않는다. MV 위임을 원곡·원문 개작 권한으로 확대하지 않는다.

동일 실패 자동 재시도 최대 1회, 검토 수정 최대 2회다. 생성·렌더 재시도는 예산과 원인 확인 후에만 한다. `uncertain:true`는 재제출 전에 상태·대기열·결과를 확인한다. 이전 실행을 보존하고 변경 입력과 downstream만 새 실행에서 검증한다.

최종 보고: 선택한 장르×형식×look, 실제 결과 경로, 참조·인기 근거/선정 이유, 관찰 프레임 수/총수, 이미지 프롬프트·파일·참조 계보, 실제 모델·옵션, 검수 근거, 결함·미실행 항목. 파일 존재·동일 seed만으로 캐릭터 동일성을 보장하지 않는다. 청취·재생·생성하지 않은 결과를 평가하지 않는다.

## 제작실에 결과 연결

공통 제작실을 사용하는 납품은 `../road-music-video-studio/references/result-contract.md`의 선택적 제작 자료와 등록 전 계획을 따른다. 최종 영상·원음·원가사·자막·스토리보드와 실제 기획/검수 JSON·명시적으로 묶은 편집 소스 ZIP만 등록한다. 모델·캐시·전체 작업 폴더를 납품 ZIP에 자동 포함하지 않는다. LTX 감독형 제작은 Showreel 편집형과 구분하고, 원본 타이밍·완성 파일·기존 제작 기록은 보존한다.

## 음악별 저장공간과 프로젝트 종료 정리

같은 원음의 M/V 버전은 원음 SHA로 묶고, 재생성 캐시를 프로젝트 `.roadmusic/cache/`에 분리한다. 원시 프레임 전체를 단계마다 중복 복제하지 않고 필요한 검수 증거와 입력·출력 해시·판정 요약을 남긴다. 실제 제작 프로세스의 잠금을 유지하고 성공한 단계와 실패 후 재개 자료를 구분한다. 프로젝트 정책·핀과 용량 예산을 확인하며 모델·원음을 매 작업 복사하지 않는다.

사용자가 애니매틱·최종 영상까지 포함해 AI M/V 프로젝트를 통째 정리하라고 요청하면 `road-music-storage`의 [전체 정리 절차](../../../skills/road-music-storage/references/mv-project-removal.md)를 적용한다. `storage:mv-list`의 원음·프로젝트 ID와 최신 전체 스캔으로 계획하고 공개 CLI/HTML로 실행한다. 일반 캐시 정리 권한을 최종 영상 삭제로 확대하지 않으며, 명시된 전체 삭제에서는 해당 프로젝트 출력까지 포함하고 외부 원본 음악·모델과 프로젝트 밖 최소 요약을 보존한다.

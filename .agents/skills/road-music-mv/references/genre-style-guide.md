# 음악 장르 × 영상 형식 × 화면 스타일

장르는 음악, 형식은 영상 구성, 화면 스타일은 미술·촬영 표현이다. `발라드=서사형`, `트로트=밝은 무대`, `아이돌=댄스곡`으로 고정하지 않는다. 사용자의 선택과 실제 곡의 편곡·감정·타깃이 기본 추천보다 우선한다. 아래는 제작 출발점인 **설계 권고**이며 인기 작품에서 측정한 통계나 모델의 전용 옵션이 아니다.

## 선택할 축

| 축 | 예 | 결정할 것 |
|---|---|---|
| music_genre | ballad, rock-ballad, trot, pop/dance, rock, hip-hop, R&B, jazz 등 자유 입력 | 호흡·강약·리듬·악기 사건·가사의 감정 |
| visual_format | idol-performance, band-live, solo-live, narrative, cinematic-montage, conceptual, animation, hybrid | 무엇을 보여주고 어떻게 연결하는가 |
| visual_look | photorealistic, film-retro, polished-stage, neon, minimal, anime, 3D 등 자유 입력 | 인물·공간·빛·재질·색·카메라의 통일 |
| performance_source | generated-performance, recorded-live, hybrid | 가상 공연 장면과 제공받은 실제 공연 기록 구분 |

장르·형식을 임의 문자열로 확장할 수 있다. 이 필드는 기획 JSON의 선택값이며 Road Music/LTX의 새 CLI 플래그가 아니다. 혼합곡은 primary genre와 `subgenres`, 곡·편곡 버전, 근거 또는 사용자 지정임을 함께 기록한다. 장르 이름만 보고 원곡을 재편곡하지 않는다.

같은 조합 안에서도 인원·공연/서사 비중·카메라 강도·컷 밀도·팔레트·시대/장소·의상·화면비를 기획에 반영한다. 각 선택은 실제 샷과 이미지 프롬프트의 구도·동작·빛·미술로 이어져야 한다. 옵션 이름만 바꾸고 동일 프롬프트를 반복하지 않는다.

|---|---|---|---|
| 발라드 | 솔로 라이브·서사·절제된 퍼포먼스·혼합 | 프레이즈/감정 변화에 컷, 얼굴·손·시선과 여백, 느린 이동을 선택적으로 사용 | 인물 마스터·표정·의상, 주요 관계 공간, 감정 구간별 샷 기준 이미지. 표정·나이·얼굴 drift 검사 |
| 록발라드 | 밴드 라이브·서사/밴드 교차·가상 공연 | 조용한 구간과 후렴의 프레이밍/빛/컷 밀도 대비, 악기 사건에 인서트 | 멤버별 마스터·역할/악기·무대 위치·조명 상태·객석 방향. 운지·마이크·악기 형태·립싱크 proof |
| 트로트 | 정통 무대·감성 서사·현대 퍼포먼스·복고 | 가사 전달과 제스처, 정통/발라드/댄스 트로트의 실제 정서를 구별 | 인물·무대 의상·소품·시대와 장소 이미지. 얼굴 표정·제스처 가독성·연령/복식 연속성 |

| 재즈/어쿠스틱/연주 | 스튜디오 라이브·공간 몽타주·추상 | 호흡·악기 응답·공간감, 연주자 없는 풍경도 실제 요청에 맞게 선택 | 필요한 연주자만 캐릭터화, 악기/실내 배치·배경 이미지. 연주 정확도·긴 샷의 drift 검사 |

CCM 등 다른 장르도 같은 축으로 확장한다. 신앙 내용을 요청하지 않은 곡에 임의로 넣지 않는다. 전문 음악 작업까지 포함되면 프로젝트의 해당 가이드를 별도로 읽는다.

## 형식별로 달라지는 기획과 이미지

- **아이돌 퍼포먼스**: 멤버 개별 마스터와 그룹 배치가 별개다. 각 인물의 얼굴·체형·헤어·고유 의상/색을 구별하고 솔로 샷과 그룹 샷의 인원을 명시한다. 그룹 사진 하나로 모든 멤버의 정체성이 확보됐다고 처리하지 않는다.
- **밴드 라이브**: 멤버·역할·악기와 무대 동선을 고정한다. 실제 공연 기록은 원본 영상/오디오를 보존한다. 생성한 공연 장면은 가상 라이브형 MV로 표시하며 실제 현장 기록이라고 주장하지 않는다.
- **솔로 라이브**: 얼굴·마이크·손·스탠드·반주자/악기의 위치와 카메라 축을 고정한다. 기존 음원 mux만으로 실제 가창 싱크를 충족했다고 하지 않는다.
- **서사/시네마틱**: 시간·공간·관계·소품의 연속성을 설계한다. 회상/현재의 의상·나이 변화는 의도된 버전으로 관리하고 뜻밖의 얼굴 변화와 구분한다.
- **애니메이션/3D**: 실루엣·비율·선·눈/입 형태·재질·렌더링 스타일을 캐릭터시트에서 고정한다. 실사 앵커에서 그림체만 샷마다 새로 추정하지 않는다.
- **혼합형**: 구간별 형식·의상·공간을 배정하고 같은 인물이라는 공통 anchor를 유지한다. 공연과 서사 사이의 전환 근거를 적는다.

## 장르·형식별 레퍼런스 분석

[genre-references.json](genre-references.json)의 후보와 기존 코퍼스를 함께 쓴다. 사용자 레퍼런스가 우선이다. 선택한 조합에 음악 장르가 맞는 작품, 영상 형식이 맞는 작품, 필요하면 다른 접근의 비교작을 고른다. 같은 곡의 MV/라이브 비교는 음악을 고정한 채 형식 차이를 관찰하는 데 유용하다.

인기 주장은 `popularity_scope`(음원/MV/라이브), 지표, 집계 기간, 관측일, 공식 출처, 현재/과거 여부를 기록한다. 음원 차트 성과를 MV의 조회수나 연출 우수성으로 바꾸지 않는다. 과거 대표곡을 현재 인기작으로 표시하지 않는다. 최신 근거가 없으면 미확인 상태를 유지하고 실제 제작 실행일에 다시 조사한다.

작품마다 다음을 실제 관찰한다: 구간별 공연/서사 비중, 인물·악기·공간의 노출, 샷 크기·앵글·이동·컷 길이, 음악 사건과 전환, 팔레트/의상/장소 반복, 인물 일관성을 유지하는 방식. `analysis-protocol.md`의 원본·PTS·검토 coverage를 유지한다. 아직 보지 않은 영상에 타임코드나 카메라 분석을 채워 넣지 않는다.

결과는 `선택한 장르+형식+look → 레퍼런스의 관찰 근거 → 차용할 원리/변경점 → 샷 설계 → 필요한 이미지 목록 → 검수 기준`으로 연결한다. 예쁜 이미지 모음만으로 음악과 맞는 기획을 대체하지 않는다.

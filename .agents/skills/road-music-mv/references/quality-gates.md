컷은 계획의 목표 frame과 비교한다. 납품 한 프레임 이내 차이를 검토 출발점으로 쓸 수 있지만 음악적 의도·사용자 조건이 우선이다. 립싱크의 입 모양·음절·음원 관계는 별도 검수하며 컷 허용치로 대신하지 않는다.

멤버의 좌우 순서는 해당 샷·연속 장면에서 명시한 대형과 공간축에 맞춰 판정한다. 다른 장면의 일렬 대형을 순서가 고정되지 않은 원호 대형에 자동 적용하지 않는다. 단일 생성 이미지의 물리 카메라 각도·렌즈 수치는 입증할 수 없으므로, 선언한 높은 시점·측면·프레이밍이 실제로 보이는지와 수치적 촬영 의도를 구분한다.

같은 인계 음원·길이·표시 조건에서 나온 **MV 영상 후보**를 비교한다. 감정/서사, 음악과 동작, 구도/빛, 연속성, 효과 목적을 근거와 함께 평가한다. 이 비교는 음악 후보·음질 선정을 대신하지 않는다. 점수 합계가 신체 오류·입력 누락을 덮지 못한다. 임의 90점·명작 판정을 완료 조건으로 강제하지 않는다.

## 실패·재개

동일 실패 원인 확인 후 최대 1회 추가 시도, 리뷰 수정 최대 2회다. 사용자 예산이 먼저 끝나면 중단한다. 단순 프레이밍·짧은 구간·후반 합성 등 대안을 제시하되 원 요구를 충족했다고 위장하지 않는다. 새 모델 다운로드·유료 API·외부 게시를 자동 대안으로 실행하지 않는다.

입력·프롬프트·모델·seed·편집이 바뀌면 해당 노드와 downstream을 검증한다. `run.py resume`으로 새 run을 만들고 과거 기록을 보존한다. 외부 파일은 같은 경로여도 SHA-256이 다르거나 PTS가 달라지면 stale이며, 원본 관찰·coverage·샷/전환 근거는 새 source에 다시 결속해 재검수한다. 생성·렌더 연결이 불확실하면 상태 확인 전 재제출하지 않는다.

캐릭터·의상·배경·소품·샷 이미지가 바뀌면 해당 검수와 이를 참조하는 보드·애니매틱·샷·최종 검수를 무효화한다. production-design/image-plan/shot-plan/storyboard 중 하나가 바뀌면 전역 보드·애니매틱 검수를 다시 결속한다. 이 네 문서의 digest는 정렬·compact·UTF-8 canonical JSON SHA-256이며 raw 파일/source SHA와 다르다. 하네스 입력 fingerprint도 `file\0` 도메인을 쓰므로 별도 비교한다.

전체 제작은 `--production-design`·`--storyboard`와 단계별 `--stage`를 사용한다. Bible이 있으면 기존 context binding 검사도 함께 적용한다. 기존 이미지-only 호출의 `--require-ready`는 키시트/이미지 보드/애니매틱 전체 준비를 뜻하지 않는다. 얼굴 동일성·좋은 이야기·독립 관찰은 해시·선언만으로 입증되지 않으며 실제 비교/재생이 필요하다. [전체 연출](creative-direction.md), [이미지 선행 제작](image-preproduction.md)의 계약과 도구를 따른다.

애니매틱은 무손실 오디오를 유지하는 `preproduction/animatic.mov`를 기본으로 하며 원본 sample rate/channels를 보존한다. 다른 컨테이너도 실제 정규화PCM 신호가 일치하면 사용할 수 있지만 손실 재인코딩으로 달라진 신호를 선언만으로 통과시키지 않는다. 이는 음악 품질 평가가 아닌 원곡 유지 검사다. 최종 MV master의 MP4 납품과 구분한다.

하네스의 각 노드는 논리 입력의 실제 산출물 생산자에도 직접 의존한다. 순서상 직전 노드만 의존하면 계획 파일이 dependency artifact fingerprint에서 빠질 수 있다. 패널 `at_frame`과 페이지는 전체 시간 순서대로 엄격히 증가하며 중복·역행을 허용하지 않는다.

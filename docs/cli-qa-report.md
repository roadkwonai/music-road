## 1.4.0 GitHub 업데이트 검증 (2026-10-15)

- `npm test`: **119/119 통과**, 실패·건너뜀 없음. JavaScript 60개 구문 검사와 diff 공백 검사도 통과했다. 공개 CLI는 **115개 명령**이다.
- 다운로드 해시·크기 검증, 파일 변조 거부, 부분 파일 정리, 잘못된 CDN 리디렉션 거부, 다운로드 중 검사 경합, 실패 후 재시도, 설치 명령 시간 초과·SIGTERM 무시 자식 강제 종료를 검증했다.
- 별도 데이터 폴더의 실제 Electron에서 `update:status`, GitHub `update:check`, `update:watch` 제한 시간 응답을 확인했다. 생성·설치·렌더 준비 단계의 예약으로 설치와 새 작업의 경합을 막는다.
- `node scripts/verify-cli.js --gpu`: 음원 가져오기·MP3·앨범·SRT·CPU/GPU 720p MP4·서비스 종료까지 통과했다.
- 1.3.1 앱을 임시 폴더에 복사한 뒤 새 DMG로 **실제 1.4.0 교체·재시작**했다. 곡·모델·설정 보존, 설치 결과 조회, 이전 앱 백업을 확인했다. 사용 중인 앱과 기존 라이브러리는 교체하지 않았다.
- 실제 renderer에서 새 버전 응답을 주입해 우측 상단 배지, 자동 팝업 없음, 클릭 시 변경 내용·설치 버튼 표시를 확인하고 화면을 검토했다. Git fixture로 fast-forward·의존성 교체와 실패 시 기존 HEAD·의존성 복구를 확인했다.
- `codesign --verify --deep --strict`와 `hdiutil verify`로 새 앱·DMG를 검사했다. 현재 서명은 애드혹이며 Developer ID·공증·다른 Mac의 Gatekeeper 동작은 검증하지 않았다.

Windows 자동 설치·비-Git ZIP 키트 자동 소스 교체는 지원하지 않는다. Linux 경로는 실제 설치 검증을 하지 않았다. 이 변경에서 모델 재설치·신규 음악 생성·실제 마이크·YuE 검증은 반복하지 않았다. 사용 계약과 배포 방식은 [업데이트 가이드](updates.md)를 따른다.

아래 내용은 1.3.1 CLI 구축 당시의 검증 기록이다.

## 판정과 적용 범위

검수 중 발견한 데이터 보존·동시 실행·작업 대기·녹음 오류를 수정하고 회귀 테스트를 추가했다. 아래 표는 실제 실행, 오류 주입 테스트, 미실행을 구분한다. 공개 스키마에 명령이 있다는 사실만으로 해당 기능을 실제 검증한 것으로 계산하지 않는다.

독립 코드 리뷰 최종 판정은 `APPROVE`, 아키텍처 검토는 `CLEAR / APPROVE`다. 발견한 차단·주요 결함은 수정과 재검증을 완료했다.

테스트는 별도 임시 데이터 폴더와 곡 라이브러리에서 실행했다. 실제 ACE 생성만 기존 설치 모델을 재사용했으며, 사용자의 실제 곡 라이브러리나 모델 위치를 옮기지 않았다. 성공한 통합 검증은 테스트 서비스를 종료하고 임시 파일을 지운다.

## 실행 증거

환경: macOS Apple Silicon `arm64`, Node.js `v24.21.0`, Electron `33.4.11`, ffmpeg `9.0.2`.

| 검증 | 결과 | 확인한 내용 |
| --- | --- | --- |
| `npm test` | 103/103 통과, 실패·건너뜀 0 | 스키마, 소켓, 배치, 타임아웃, 파일 보존, 재시작, 재시도, 녹음 실패, 설정·라이브러리 이동, 패키지·CLI ZIP 구성·문서 예제 |
| JavaScript `node --check` | 52개 파일 통과 | `cli/`, `electron/`, `renderer/`, `scripts/`, `tests/`의 JS 구문 |
| Python `ast.parse` | 6개 파일 통과 | `python/`의 Python 구문, 캐시 파일 생성 없음 |
| `node scripts/verify-cli.js --generation --gpu` | 종료 코드 0 | 실제 Electron·ffmpeg·ACE-Step 통합 |
| `node scripts/verify-cli-extended.js --player` | 28개 그룹 통과 | 상태·서비스, 프로젝트·곡·앨범·자산·프리셋·설정, 실제 재생, MIDI 변환, 대기열 조작·재시도·재시작 보존 |
| `node scripts/verify-cli-video-matrix.js` | 렌더 8건 + 취소 1건, 9/9 통과 | 아래 영상 옵션 및 출력 메타데이터, 기존 파일 보존 |

별도 ESLint·TypeScript 설정이나 빌드 단계는 없다. 존재하지 않는 검사 도구의 통과를 주장하지 않고 Node 구문 검사와 동작 테스트를 실행했다. 패키지 검사는 `npm pack --dry-run`으로 실행하며 설치·세션 상태와 Python 캐시가 포함되지 않는지 확인한다.

OMX LSP 진단 도구는 `Transport closed`로 실행할 수 없었다. 따라서 LSP 검사 통과를 검증 근거에 포함하지 않았다.

### 실제 음악 생성과 입출력

- ACE-Step 무반주 곡 2개를 한 요청으로 생성하고 각각 다른 작업 ID·폴더, 완료 대기 및 결과 재조회를 확인했다.
- 한국어 가사가 있는 보컬 곡, 가사 SRT, 2초 효과음, 기존 곡 오디오 커버, 가져온 녹음 파일 기반 생성을 실행했다. 출력 음원은 `ffprobe`로 길이가 양수인지 확인했고 효과음 길이 및 커버 강도 메타데이터도 확인했다.
- 한글·공백 경로의 음원 가져오기, 제목 변경, MP3/WAV·앨범 내보내기, SRT 파일 저장을 확인했다.
- 플레이어의 재생·일시정지·탐색·다음·이전·정지를 실제 Electron 오디오 경로로 확인했다. 음질·가창 정확도는 청취 평가 대상이 아니었다.

### 실제 영상 옵션

8개 사례에 다음 옵션을 배치해 각 값이 최소 한 번 실제 렌더되도록 확인했다. 모든 가능한 옵션의 전체 조합을 실행한 것은 아니다.

| 축 | 실행한 값 |
| --- | --- |
| 스펙트럼 | `bars`, `mirror`, `line`, `circle` 및 숨김 |
| 해상도 | `720p`, `1080p`, `1440p`, `2160p` |
| 프레임율·인코더 요청 | `30`, `60` FPS · `cpu`, `gpu` |
| 길이 | `once`, `repeat`, `minutes`의 1분 |
| 배경 | 없음, 이미지, 영상, 곡별 이미지 |
| 표시·음향 | 로고, 트랙리스트, 자유 좌표, EQ 켜기/끄기·프리셋·사용자 게인 |
| 재사용·순서 | 오디오·분석 캐시 재사용, 역순 트랙 및 챕터 |

각 파일의 H.264/AAC 스트림, 해상도, FPS, 길이, BT.709·TV 범위, 실제 저장 경로 및 크기를 `ffprobe`와 파일 검사로 확인했다. 미리보기/렌더 비교 사례는 SSIM ≥ 0.99, 프레임 오프셋 0을 확인했다. 렌더 중 언어·프로젝트 변경은 `BUSY`로 거부되어 화면 상태가 유지됐다. `gpu` 요청의 성공은 확인했지만 모든 드라이버·하드웨어에서 같은 인코더가 사용된다는 보장은 아니다.

추가로 2160p·60 FPS·CPU 영상이 실제 렌더 단계에 들어간 뒤 취소했다. `cancelled` 오류, 기존 덮어쓰기 대상 파일의 바이트 보존, staging·렌더 임시 폴더 정리, idle 상태 복귀 및 이후 설정 명령의 성공을 확인했다.

## 문서와 재현

사용 순서·응답·플래그는 [CLI 가이드](cli.md), 공개 명령과 중첩 필드의 전체 표는 [CLI 레퍼런스](cli-reference.md), 호출 경계는 [CLI 설계](cli-design.md)에 정리했다. 현재 실행 버전의 `schema`가 최종 입력 계약이다.

문서 회귀 테스트는 공개 명령 111개가 모두 레퍼런스에 있는지, 가이드의 `--json`과 JSONL 배치 예제가 인수 파서·공개 입력 스키마를 통과하는지 검사한다. CLI 제어는 Unix socket/named pipe를 쓰며, 영상 프레임용 임시 loopback HTTP 서버는 별도로 사용한다. 관련 설명·시간 제한·실패 JSON·배치 종료 코드도 실제 구현에 맞춰 수정했다. npm 배포 파일에는 CLI 가이드·레퍼런스·설계·검수 결과가 모두 포함된다.

```bash
npm test
node scripts/verify-cli-extended.js --player
node scripts/verify-cli-video-matrix.js
node scripts/verify-cli.js --generation --gpu
```

실제 생성 검증은 기본 Road Music 데이터 폴더에 ACE-Step 설치가 완료되어 있어야 한다. 영상·음원 검증은 `ffmpeg`와 `ffprobe`가 필요하다. 위 스크립트의 `--player`는 실제 소리를 재생하며 GPU·생성 검증은 시간을 사용한다. 하드웨어 경합을 피하려면 무거운 검증은 순서대로 실행한다.

## 미검증과 남은 한계

- 실제 마이크 장치·OS 권한 팝업: 오류·정리 동작은 모의 장치로 검증했다. 실제 녹음 대신 파일 가져오기 및 해당 원본의 음악 생성은 실행했다.
- Windows/Linux, YuE 실제 생성·이어 만들기·악보 합성·공식 ABC 검사: 현재 macOS 환경에서 실행하지 않았다. MIDI/ABC 열기·MIDI 변환과 미설치 오류 경로는 실행했다.
- 모델 신규 다운로드·설치, 실제 대용량 모델 이동, 실제 외장 디스크의 단절·공간 부족: 실행하지 않았다. 임시 파일·내부 심볼릭 링크·설정 실패·`EXDEV`/권한 오류를 주입한 테스트로 이동 안전성을 확인했다.
- 외부 피드백 전송, 브라우저·파일 관리자 열기: 사용자에게 영향을 주는 외부 부작용을 실행하지 않았다. 네트워크 상태·공지 결과는 실행 시점과 서비스 상태에 따라 달라진다.
- 장시간·최대 길이 생성/렌더, 모든 옵션 조합, 생성 음악의 청취 품질: 이번 검증에서 보증하지 않는다.

따라서 이 결과는 위 환경과 실행 범위에 대한 검증이며, 모든 OS·장치·원격 서비스의 모든 기능이 완전히 검증됐다는 의미가 아니다.

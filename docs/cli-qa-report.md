특정 버전과 환경에서 수행한 CLI 검수의 기록이다. 현재 설치본의 동작 보증이 아니므로, 실제 명령과 입력값은 `schema`와 [CLI 레퍼런스](cli-reference.md)로 다시 확인한다.

현재 재초기화한 0.1.0 배포물은 [앱·CLI 초기화 검증](version-reset-qa-report.md)에 별도로 기록했다. 초기화 전 첫 CLI의 설치 시험은 [이전 CLI 독립 업데이트 검증](cli-update-qa-report.md)에 보관한다. 아래의 과거 버전·해시를 현재 설치 파일에 적용하지 않는다.

## 최신 공개 schema 요약 (로컬 소스, 2026-10-19)

최신 로컬 소스의 `schema`는 공개 명령 **190개**를 기준으로 문서·카탈로그·입력 제한을 대조한다. 이 수는 현재 소스의 공개 스키마 항목 수이며, 각 명령의 실제 서비스·엔진·하드웨어 성공을 뜻하지 않는다. 특히 생성·영상 렌더 연결 오류의 `uncertain:true`는 재제출 전에 `service:status`, `queue:list`, `video:state`, 결과 파일 경로를 확인하는 복구 경계로 검수한다. 설치본의 최종 기준은 항상 해당 설치에서 실행한 `node cli/road-music.js schema`다.

## 그룹 상세·좋아요·업데이트 HTML 검증 (로컬 소스, 2026-10-19)

그룹 상세의 제작 기록에서 해당 groupId의 메인/이력 요청·AI 응답·결과·작업·파일을 직접 조회하고 원문을 복사한다. 목록/상세의 좋아요와 좋아요 전용 검색·날짜·빈 상태를 SQLite와 연결했다. 공개 로컬 명령 `works:list`, `works:favorite`를 추가했으며 그룹 전체 제거·복구 범위에 좋아요도 포함한다.

프로그램·스킬 버전 상태는 기존 공개 업데이터에 확인·실행을 연결한다. 대상 확인 창, 실제 단계/불확정 진행 막대, 완료·실패·설치 확인 필요 상태와 확인 버전 갱신을 검증했다. 응답 유실은 자동 재제출하지 않고 SQL job/최근 요청으로 조회한다. 업데이트 job은 진행/미확정 기록을 보존하고 완료 기록만 최근 40개를 유지한다. 스킬 개별 항목과 묶음은 같은 설치 범위로 차단·검증한다. 앱·CLI·스킬의 확인 필요 상태는 실제 설치 버전 증거로만 해소한다. 단순 버전 상태 조회는 기존 DB에 스키마를 만들거나 네트워크 업데이트를 검사하지 않는다.

전체 `npm test` **350/350**, 업데이트 작업 회귀 **11개**, 변경 JavaScript **12개**·Python **11개** 구문 검사와 스킬 validator 3개를 통과했다. 테스트 일부는 전체 검사에 포함되므로 합산하지 않는다. 독립 검수에서 중단/응답 유실/동시 서버/묶음 별칭/보존 한도/좋아요 재렌더 경계를 재현해 수정했다. 기존 대기 시간 테스트는 네트워크 전송에 쓴 시간을 뺀 잔여 timeout을 허용하도록 보정했다.

Ego 실제 HTML에서 두 그룹의 기록 격리·원문 복사·좋아요 저장 후 검색 재렌더·좋아요 전용 목록·390px 화면을 확인했다. 격리 설치본에서 공개 스킬 업데이터와 로컬 Release fixture로 **0.0.1→0.0.2→0.0.3** 실제 다운로드·체크섬 검증·파일 교체를 실행하고, 스킬 8개의 설치 파일 해시와 SQLite 버전·화면 완료를 대조했다. 이 버전은 검증 fixture이며 실제 배포 버전이 아니다. 기본 프로그램·모델에 업데이트를 설치하거나 새 Release를 게시하지 않았다. 기본 제작실만 현재 프로젝트를 유지해 새 소스로 열었다.

최소 검증 증거는 `.roadmusic/maintenance/group-features-20261019/`에 보관한다. 실제 앱 교체·재시작과 CLI 새 버전 설치, Windows/Linux 실기는 이번 검증에서 수행하지 않았다. 앱 재시작/CLI 경로와 스킬 소스 체크아웃 보호 조건은 [업데이트 안내](updates.md)와 [제작 기록 안내](production-records.md)에 설명했다.

## 제작 프롬프트·성능·버전 원장 검증 (로컬 소스, 2026-10-19)

`production:*` 로컬 명령 11개와 HTML `/dashboard/`를 추가했다. 프로필 `storage.sqlite3`는 최초 제작 요청, 수정 요청, 사용자 원문과 엔진 입력, 대기·실행·완료 상태, AI/결과 요약, 파일 메타데이터와 버전 관찰을 연결한다. 음악별 상세에서 제작 분석으로 이동하며 원문을 개별 복사한다. 조회는 DB를 생성·이전하거나 파일·Git 전체를 검사하지 않는다. 실제 새 제작부터 측정하며 이전에 기록하지 않은 원문·시간은 추정하지 않는다.

전체 `npm test` **346/346**을 통과했다. 별도 Showreel native **34개**, JIZURA 프로젝트 **15개**, updater **14개**, 공개 조회 필터 **18조건**과 JavaScript/Python 구문을 검증했다. 이 검사들은 일부 중복되므로 합산하지 않는다. 독립 검수에서 파일 순회 실패의 불완전 목록 표시와 업데이트 확인의 비동기 저장 경합을 재현해 수정했고, 동시 확인·EACCES·오래된 DB·긴 UTF-8 원문·파일 5,000개 초과 스트리밍·부모/단계 중복 집계 회귀를 고정했다.

격리 프로필에서 실제 공개 CLI로 제목·가사를 수정하고 2초 CPU MP4를 제작했다. 마지막 실행은 준비 **54.868ms**, 렌더 **892ms**, 실제 길이 **2초**였고 한 사용자 요청에 별도 엔진 입력과 작업/파일이 연결됐다. 검수 task의 AI 응답과 결과 요약도 HTML에서 함께 확인했다. 계획된 프레임 수를 실제 렌더 프레임으로 기록하지 않는다. 합성 WAV·영상 fixture와 제어된 worker 실패 시험은 실제 AI 음악 추론 성능으로 계산하지 않는다.

Ego에서 프로젝트 162개와 한 프로젝트의 요청 73개를 페이지로 조회하고 화면 행 상한 120개, 메인/이력 원문 복사, 한글 Paperlogy, 안내 모달·가이드 복사, 320px 화면을 확인했다. 일별 추이와 조건별 평균 그래프, 중앙값·p95·같은 조건의 느린 작업을 표시한다. 프로그램 2개와 스킬 묶음/개별 스킬 9개 총 11개 버전 관찰을 확인했으며, 소스 버전은 설치 완료와 구분한다. 업데이트는 확인만 했고 설치하지 않았다.

기본 앱·제작실은 유휴 상태에서 새 소스를 반영했다. 임시 프로필·검증 미디어 **71개**를 제거했고 기존 Output 완성 파일 **35개·1,285,667,500B**의 크기와 SHA-256은 동일하다. 최소 증거는 `.roadmusic/maintenance/production-records-20261019/`에 남겼다. 신규 모델 추론·직접 청취·Windows/Linux 실기·릴리스 배포는 이번 원장 검증에서 실행하지 않았다.

## SQLite 소유권·변경 이력과 실제 정리 검증 (2026-10-19)

프로필 `storage.sqlite3`에 프로젝트·음악 그룹·경로 소유권·최소 변경 이벤트·파일 stat 색인을 모았다. `.roadmusic/history.sqlite3`는 납품 버전·파일·diff 원장을 유지한다. 미디어·가사·엔진 프로젝트 JSON과 삭제 직전 대조용 동결 스캔은 파일로 보존하며, 일반 조회에서 원문 미디어 해시·전체 Git 검사·자동 VACUUM을 수행하지 않는다. 기존 관리 JSON은 검증 후 일회 이전하고, 이후 SQLite를 우선한다. 새 검수 피드백은 JSONL을 계속 쌓는 대신 SQLite 전후 이력에 기록한다.

실제 미연결 표시 원인은 관리 영역의 미분류, 현재 보관함에서 중복 해시로 생략된 과거 납품 경로, 제작실 재실행 시 기존 소유권의 workspace/group을 빈 값으로 덮어쓰는 중복 저장이었다. 분류·납품 원장 기반 복구와 중복 저장 제거로 보완했다. `.roadmusic/work`는 상위 관리 폴더 소유권을 무조건 상속하지 않으므로 실제 고아 파일은 여전히 보호 대상으로 드러난다. 신규 작업은 제작 전에 소유권을 기록하고, 음악 생성의 추적 저장이 실패하면 대기열 제출을 중단한다.

Ego HTML에서 격리 프로필의 2초 합성 저장공간 fixture를 게시·재게시하고 제목/가사 이력, 버전 diff, 설명 모달을 확인했다. 그룹 전체 제거로 작업 1개·납품 버전 2개·파일 12개를 제거한 뒤 해당 프로젝트/그룹의 관리 이벤트·경로·납품 행이 모두 0개임을 확인했고 외부 원음은 유지됐다. 합성 fixture는 AI 음악·Showreel 제작 검증으로 계산하지 않는다. 테스트 프로필과 임시 미디어도 종료 후 제거했다.

실제 기본 프로필을 이전·색인하고 HTML에서 `.DS_Store` 2개를 정리해 **파일 할당량 16,384B**를 확보했다. 최종 미연결 자료는 **0개/0B**다. 기존 Output 완성 파일 **35개·1,285,667,500B**의 크기와 SHA-256은 전후 동일하며 모델·프로그램은 정리 대상에 포함하지 않았다. 소유권 연결 복구를 삭제로 확보한 공간으로 계산하지 않는다. 실제 증거는 `.roadmusic/maintenance/sqlite-ownership-20261019/`에 최소 JSON·화면으로 남겼다.

기본 프로필의 공개 조회는 이번 Mac에서 tracking 0.766초, list 0.187초, events 0.138초였고 조회 전후 관리 DB의 크기·수정 시각이 동일했다. 이는 해당 측정의 값이며 일반적인 속도 보장은 아니다. 전체 `npm test` **326/326**, native 프로젝트 **33개**, HTTP 저장공간 **23개**, 게시 계약 **9개**와 JavaScript/Python 구문 검사를 통과했다. 일부 검사는 전체 테스트와 중복되므로 고유 테스트 수로 합산하지 않는다. 남는 하위 프로젝트·제작 마커의 공유 입력 보호, 재등록 중복 스캔 방지를 독립 검토했다. 실제 앱은 빈 대기열을 확인한 후 안전하게 재시작했다.

상세 Markdown을 공통 HTML 가이드 `/guide/storage-tracking/`로 렌더하고 Paperlogy 로딩·설명 모달·원문 복사 버튼을 확인했다. 실제 신규 모델 추론·청취·Windows/Linux 실기·릴리스 배포는 이번 소유권 검증에서 반복하지 않았다.

## 완성본 전용 Output·SQLite 설치 점검 (로컬 소스, 2026-10-19)

`setup:check`가 엔진 준비 상태와 별도로, 관리 runtime 우선·시스템 Python fallback 순서로 Python 3 표준 `sqlite3`를 확인하도록 회귀를 추가했다. SQLite는 별도 서버·npm 의존성이 아니며 검사도 다운로드·설치를 수행하지 않는다. `tests/setup-check.test.js`에서 macOS/Windows 엔진 제외 규칙과 SQLite 미확인 시 엔진 준비 결과를 보존한 실패 표시를 검증했다.

CLI ZIP과 npm 패키지 검사에서 저장공간 스킬의 agent 정의, 완성본 전용 Output 구조 전환·archive history 도구, HTML 저장공간 가이드가 포함되는지 확인했다. 가이드 Markdown 렌더·복사 검사도 통과했다. 이 절은 실제 사용자 프로젝트의 구조 전환·삭제 또는 새 모델 설치를 수행한 기록이 아니다.

## YuE2 CLI 확장과 실제 음원 검증 (로컬 소스, 2026-10-19)

고급 옵션 16개·63비트 seed·상세 편성·runtime·단계 재사용·별도 음악 전사를 확장하고 전체 `npm test` 307/307, 구문·Python 컴파일·스킬 validator·독립 코드 검수를 통과했다. CLI ZIP의 실제 추출본에서도 새 파일과 로컬 사전검사·공식 ABC 도구를 확인했다. 최종 회귀에서 명령 `exit`와 stdout 종료의 경합을 재현해 `close`까지 출력 수집을 기다리도록 수정했다.

M1 Ultra 64GB의 격리 프로필에서 8개 비교 음원을 완료했다. 전곡 디코딩·48kHz stereo·유한 신호·ABC 검사·잘림 없음과 원본 해시 보존을 확인했고, 전체 무유도 ASR 8건 및 문맥 구간 2건을 별도로 검수했다. 추가 계획 작업에서 실제 native 값 16개와 최대 seed를 대조했으며, 공개 취소의 terminal 1회·자식 회수·원본 계획 보존도 확인했다. 상세 수치와 권고는 [YuE CLI 실기 검증](yue-cli-validation.md)에 기록했다.

직접 오디오 입력이 지원되지 않아 청취 품질은 미확인이다. ASR을 보컬·음정·리듬·음질 점수로 바꾸지 않았다. M1 Max 32GB·Windows 실기·SheetSage2·실제 LoRA 음원 추론은 미검증이며, 새 모델 설치나 기존 사용자 서비스 변경·배포는 수행하지 않았다.

## 프로젝트 저장공간 관리 (로컬 소스, 2026-10-19)

최종 실사용 보완 소스에서 `npm test` 281/281, 저장공간 Python core/legacy/lifecycle/HTTP 49개, 기존 native 프로젝트 28개와 playlist 12개가 통과했다. 각 검사에는 일부 중복이 있어 합산한 고유 테스트 수로 안내하지 않는다. JavaScript 구문, Python AST, 스킬 validator와 패키지 dry-run을 검사했다. 패키지에 작업 결과·모델·캐시가 포함되지 않았다.

## 판정과 적용 범위

검수 중 발견한 데이터 보존·동시 실행·작업 대기·녹음 오류를 수정하고 회귀 테스트를 추가했다. 아래 표는 실제 실행, 오류 주입 테스트, 미실행을 구분한다. 공개 스키마에 명령이 있다는 사실만으로 해당 기능을 실제 검증한 것으로 계산하지 않는다.

독립 코드 리뷰 최종 판정은 `APPROVE`, 아키텍처 검토는 `CLEAR / APPROVE`다. 발견한 차단·주요 결함은 수정과 재검증을 완료했다.

테스트는 별도 임시 데이터 폴더와 곡 라이브러리에서 실행했다. 실제 ACE 생성만 기존 설치 모델을 재사용했으며, 사용자의 실제 곡 라이브러리나 모델 위치를 옮기지 않았다. 성공한 통합 검증은 테스트 서비스를 종료하고 임시 파일을 지운다.

- 한국어 가사가 있는 보컬 곡, 가사 SRT, 2초 효과음, 기존 곡 오디오 커버, 가져온 녹음 파일 기반 생성을 실행했다. 출력 음원은 `ffprobe`로 길이가 양수인지 확인했고 효과음 길이 및 커버 강도 메타데이터도 확인했다.
- 한글·공백 경로의 음원 가져오기, 제목 변경, MP3/WAV·앨범 내보내기, SRT 파일 저장을 확인했다.
- 플레이어의 재생·일시정지·탐색·다음·이전·정지를 실제 Electron 오디오 경로로 확인했다. 음질·가창 정확도는 청취 평가 대상이 아니었다.

### 실제 영상 옵션

8개 사례에 다음 옵션을 배치해 각 값이 최소 한 번 실제 렌더되도록 확인했다. 모든 가능한 옵션의 전체 조합을 실행한 것은 아니다.

| 축 | 실행한 값 |
| --- | --- |
| 스펙트럼 | `bars`, `mirror`, `line`, `circle` 및 숨김 |
| 해상도 | `720p`, `1080p`, `1440p`, `2160p` |
| 프레임율·인코더 요청 | `30`, `60` FPS · `cpu`, `gpu` |

각 파일의 H.264/AAC 스트림, 해상도, FPS, 길이, BT.709·TV 범위, 실제 저장 경로 및 크기를 `ffprobe`와 파일 검사로 확인했다. 미리보기/렌더 비교 사례는 SSIM ≥ 0.99, 프레임 오프셋 0을 확인했다. 렌더 중 언어·프로젝트 변경은 `BUSY`로 거부되어 화면 상태가 유지됐다. `gpu` 요청의 성공은 확인했지만 모든 드라이버·하드웨어에서 같은 인코더가 사용된다는 보장은 아니다.

## 문서와 재현

사용 순서·응답·플래그는 [CLI 가이드](cli.md), 공개 명령과 중첩 필드의 전체 표는 [CLI 레퍼런스](cli-reference.md), 호출 경계는 [CLI 설계](cli-design.md)에 정리했다. 현재 실행 버전의 `schema`가 최종 입력 계약이다.

```bash
npm test
node scripts/verify-cli-extended.js --player
node scripts/verify-cli-video-matrix.js
node scripts/verify-cli.js --generation --gpu
```

실제 생성 검증은 기본 Road Music 데이터 폴더에 ACE-Step 설치가 완료되어 있어야 한다. 영상·음원 검증은 `ffmpeg`와 `ffprobe`가 필요하다. 위 스크립트의 `--player`는 실제 소리를 재생하며 GPU·생성 검증은 시간을 사용한다. 하드웨어 경합을 피하려면 무거운 검증은 순서대로 실행한다.

## 미검증과 남은 한계

- 실제 마이크 장치·OS 권한 팝업: 오류·정리 동작은 모의 장치로 검증했다. 실제 녹음 대신 파일 가져오기 및 해당 원본의 음악 생성은 실행했다.
- Windows/Linux, YuE 실제 생성·이어 만들기·악보 합성·공식 ABC 검사: 현재 macOS 환경에서 실행하지 않았다. MIDI/ABC 열기·MIDI 변환과 미설치 오류 경로는 실행했다.
- 모델 신규 다운로드·설치, 실제 대용량 모델 이동, 실제 외장 디스크의 단절·공간 부족: 실행하지 않았다. 임시 파일·내부 심볼릭 링크·설정 실패·`EXDEV`/권한 오류를 주입한 테스트로 이동 안전성을 확인했다.
- 외부 피드백 전송, 브라우저·파일 관리자 열기: 사용자에게 영향을 주는 외부 부작용을 실행하지 않았다. 네트워크 상태·공지 결과는 실행 시점과 서비스 상태에 따라 달라진다.
- 장시간·최대 길이 생성/렌더, 모든 옵션 조합, 생성 음악의 청취 품질: 이번 검증에서 보증하지 않는다.

따라서 이 결과는 위 환경과 실행 범위에 대한 검증이며, 모든 OS·장치·원격 서비스의 모든 기능이 완전히 검증됐다는 의미가 아니다.

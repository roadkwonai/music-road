# 가사·프롬프트 검토와 자동 생성

[Road Music](../README.md) · [문서 지도](README.md) · [릴리스 노트](../releases/README.md)

AI가 로드뮤직으로 음악을 만들 때 적용하는 공통 절차다. ACE·YuE·`yue-mlx` 모두 **초안 → 제목·가사 검수 → 수정·재검수 → 기술 검증 → 요청자 검토 → 생성** 순서로 진행한다. 한국어 제목 또는 가사가 있으면 해당 한국어 항목에 아래 한국어 검수를 적용한다. 한국어가 없으면 한국어 검수는 해당 없음이며, 다른 언어를 번역하거나 한국어 기준으로 교정하지 않는다. 가사와 프롬프트까지 모두 자동으로 정해 생성하라는 위임이 있으면 요청자 검토를 생략한다. 이 경우에도 적용 대상의 검수와 기술 검증, 생성 근거 보고는 수행한다.

> [!IMPORTANT]
> “자동”은 가사와 프롬프트의 결정부터 생성까지를 명확히 위임했을 때만 적용한다. 한 항목만 맡긴 요청이나 무응답은 승인으로 간주하지 않는다.

## 요청에 따른 모드

| 사용자 요청 | 모드 | 다음 행동 |
| --- | --- | --- |
| “한국어 여성 락발라드 1곡 만들어줘” | 기본 검토 | 가사·프롬프트·옵션을 작성·검증해 보여주고 생성 전에 응답을 기다린다 |
| “가사는 네가 써줘” | 기본 검토 | 작사를 맡긴 것이며 프롬프트까지 검토 없이 생성하라는 뜻으로 확대하지 않는다 |
| “가사는 자동, 프롬프트는 내가 검토할게” | 부분 위임 | 두 항목을 완성해 보여주고 명시한 검토를 기다린다 |
| “가사와 프롬프트까지 전부 자동으로 정하고 생성해줘” | 자동 | 위임 범위에서 두 항목을 작성·검증한 뒤 곧바로 생성한다 |
| “가사·프롬프트 검토 없이 전부 알아서 만들어줘” | 자동 | 요청자 검토를 생략하되 기술 검증과 결과 자료를 남긴다 |
| “이 가사와 프롬프트 그대로 생성해줘” | 제공안 승인 | 제공한 두 항목이 완성되어 있고 생성이 요청됐다면 같은 안의 재승인을 요구하지 않는다 |
| “가사와 프롬프트만 먼저 제안해줘” | 초안만 | 생성하지 않는다. 자동 작사를 요청했더라도 생성 권한은 아니다 |
| “기존 곡의 어색한 가사를 고쳐 새 음원까지 재제작해줘” | 지정 수정·재생성 | 허용한 가사 범위만 보완·검수하고 기존 승인 프롬프트 등 보존 조건으로 생성한다. 같은 수정·생성의 재승인은 요구하지 않는다 |
| 승인된 안에 “그대로 진행해” | 승인 후 실행 | 승인한 내용과 수량으로 바로 생성한다 |

가사·프롬프트 전체의 자동 결정과 생성까지 맡긴다는 뜻이 명확하면 정해진 문구가 아니어도 자동 위임으로 해석한다. “빨리 만들어줘”, “음악 자동 생성”, 가사 또는 프롬프트 한쪽만 맡기는 요청을 두 항목 모두의 검토 생략으로 확대하지 않는다. 같은 작업에서 이미 받은 위임은 유지하되, 사용자가 나중에 “먼저 보여줘”라고 바꾸면 그 지시를 따른다.

여러 곡은 모든 곡의 안을 한 번에 제시해 묶어서 검토받을 수 있다. 1곡 요청에 비교 후보를 임의로 늘리지 않는다. 연주곡·효과음도 가사가 없다는 사실과 사용할 프롬프트를 검토안에 담는다.

제목·길이·언어 같은 취향 정보가 빠졌다면 대화 맥락과 장르에 맞는 안을 제안하고 **가정한 값**을 표시한다. 곡 수 미지정은 1곡으로 시작한다. 기본 검토에서는 그 안을 함께 검토받고, 전체 자동 위임이면 위임 범위에서 선택한 이유를 결과에 남긴다. 필수 원문·참조 파일·권한처럼 대체할 수 없는 정보가 없을 때만 해당 작업을 보류하고 확인한다.

이 절차는 **AI의 음악 제작 워크플로**다. CLI 자체가 자연어 승인 여부를 판정하거나 대화형 검토 창을 띄우는 기능은 아니다. 사용자가 직접 JSON으로 CLI를 실행하면 기존 명령의 실행 계약을 따른다.

## 원문 보존과 근거 기반 추천

**사용자가 제공한 가사·프롬프트·명시 옵션이 제작의 기준이다.** 공식 가이드와 장르 지식은 기술 제약을 확인하고 미지정 내용을 제안하는 참고 자료이며, 사용자 원문을 다른 예시로 바꾸는 자동 편집 규칙이 아니다. `prompt:knowledge`로 문서를 읽거나 GUI에서 가이드를 열어도 입력창·원문 파일·프리셋은 변경하지 않는다.

| 받은 입력 | 지켜야 할 행동 |
| --- | --- |
| 완성 가사와 프롬프트 | 원문을 그대로 유지한다. 후렴 추가·절 삭제·번역·운율 개선·장르나 성별 교체를 임의로 하지 않는다 |
| 가사만 제공 | 가사는 유지하고 비어 있는 스타일·옵션만 제안한다 |
| 프롬프트만 제공 | 프롬프트는 유지하고 요청한 범위의 가사를 새로 제안한다 |
| 일부 줄만 수정하도록 요청 | 지정한 줄만 바꾸고 나머지 가사·프롬프트를 유지한다 |
| 기존 곡의 가사 전체를 자연스럽게 다시 쓰도록 요청 | 허용한 전체 가사를 보완하고 원문·변경 이유를 남긴다. 기존 제목·장르·프롬프트 등 사용자가 변경을 맡기지 않은 승인값은 보존한다. 가사만 요청했으면 생성하지 않는다 |
| “추천해줘” | 추천 내용과 근거를 보여준다. 원문을 수정하거나 추가 생성하지 않는다 |
| “가사·프롬프트부터 전부 자동” + 별도 원문 | 새로 결정할 부분만 위임받은 것으로 해석한다. 제공 원문 변경은 명시적으로 맡겼을 때만 수행한다 |

제안은 **현재 원문 → 바꾸려는 부분 → 이유·공식/장르 문서 근거 → 적용 여부**를 구분해 보여준다. 사용자 미지정 값은 가정한 값이라고 표시한다. 기존 제공값을 숨겨진 기본값으로 덮어쓰지 않는다. 예를 들어 남성 보컬을 지정했는데 CCM C17의 기본 여성 보컬을 우선하지 않는다.

```text
원문 가사와 style은 그대로 보존했어.
제안: 새벽 기도 분위기라면 drums를 제외한 piano·cello 편성도 가능해.
근거: docs/ccm-prompts.md의 C33~C35와 공식 가이드의 상충 지시 줄이기 원칙.
변경 범위: parts.instruments만. 아직 입력에는 적용하지 않았어.
```

### 원문과 엔진 전달본을 구분

현재 엔진 경로는 태그·가사 정리와 스타일 조합을 수행한다. 원문 파일을 보관하고 실제 경로의 `lyrics:clean`·`prompt:compose` 결과는 **별도 점검본**으로 비교한다. 정리 결과로 원문을 덮어쓰지 않는다. 원문 보존 요청과 충돌하는 삭제·정규화·악기/BPM 문구 추가·엔진별 입력 한계에 따른 잘림이 예상되면, 바뀌는 부분과 이유를 보여주고 해당 부분의 대안만 제안한다. 승인 없는 개사나 조용한 잘림으로 해결하지 않는다.

기술 제약·권리 근거가 충돌하면 “원문 그대로 실행 가능”이라고 주장하지 않는다. 새 번역·다른 원전·분할·짧은 스타일 등의 선택지를 제안하되, 승인 없이 사용자 원문이나 참조 음원을 교체하지 않는다. 이미 승인된 **동일한 전달본**의 실행에는 같은 승인을 다시 요구하지 않는다. 모델이 실제로 부르는 가사와 멜로디까지 정확히 같다는 보장은 별도로 하지 않는다.

## 새 가사의 이야기·호흡 설계

새 작사를 맡았거나 해당 범위의 개사를 허용받았을 때 적용하는 창작 선택지다. 제공·승인 원문을 이 기준에 맞춰 다시 쓰지 않는다. 이야기형 곡은 화자와 상대의 관계, 감정을 움직이는 사건이나 핵심 사물, 마지막에 달라지는 말·행동을 먼저 잡는다. 감정 형용사를 늘리기보다 연결되는 장면으로 이유를 보여주며, 소품이나 반전을 억지로 추가하지 않는다. 묵상·댄스 훅·반복 중심 곡에 줄거리를 강제하지 않는다.

- 벌스마다 같은 슬픔을 설명하기보다 관찰·기억·깨달음 중 필요한 변화를 준다. 후렴의 짧은 핵심 문장은 기억하기 쉽게 유지하고, 마지막 반복은 앞선 맥락으로 의미가 깊어지게 할 수 있다. 반복 변화가 모든 후렴의 개사를 뜻하지는 않는다.
- 호흡이 끝나는 곳에서 줄을 나누고, 대응하는 구절의 길이와 발음을 소리 내 읽듯 점검한다. 6~9음절 같은 자료의 수치는 초안 팁이며 고정 규칙이 아니다. 느린 BPM이어도 가사가 빽빽하면 빠르게 불릴 수 있다. 늘임표·모음 반복으로 고음이나 정확한 발음을 보장하지 않는다.
- 제목을 새로 정하는 범위라면 핵심 사물·장면·후렴에서 곡을 구별할 이름을 찾는다. 후보 수·스타일 수·언어는 요청을 따르고, 참고 자료의 기본 3안이나 한국어 기본값을 별도 요구로 추가하지 않는다.

이 설계는 [사용자 제공 자료에서 응용한 창작 요령](genre-prompts.md#external-adaptation)이며 모델의 공식 기능·품질 보장이 아니다. 태그 없는 문학 초안과 실제 생성용 섹션 입력을 구분하고, 생성 입력에는 해당 엔진의 가이드와 정리 결과를 적용한다. 내용 검토만 요청한 경우 설계 과정을 별도 보고서로 늘리지 않는다.

## 제목·가사 한국어 검수

한국어 제목 또는 가사가 있는 곡은 초안·부분 수정·재생성 모두 해당 한국어 항목에 이 단계를 적용한다. 한국어가 없는 항목은 한국어 검수 해당 없음으로 표시하며, 다른 언어의 자연스러움을 검증했다고 보고하지 않는다. 여러 곡은 각 곡의 해당 제목·가사를 검수하고 제목 목록도 함께 읽어 주제·표현의 불필요한 중복을 확인한다. 연주곡은 가사 없음 선언 또는 `instrumental:true`를 확인해 제목만 검수하고, 가사·후렴은 해당 없음으로 표시한다. 제목만 검토하는 요청에는 제목과 주어진 주제만으로 판정하며, 없는 가사와의 관계는 미확인으로 구분한다.

### 검수 기준

| 대상 | 확인할 내용 |
| --- | --- |
| 제목 | 제목만 읽어도 의도한 감정·장면이 전달되는가? 단어와 서술어의 결합, 명사화, 생략이 자연스러운가? 전체 가사와 어울리는가? |
| 문장 | 조사·주어·서술어의 관계, 시제·화자·호칭, 앞뒤 줄의 연결이 자연스러운가? 번역투나 의미를 복원하기 어려운 생략이 있는가? |
| 전곡의 내용 | 누가 누구에게 무엇을 말하는가? 절·후렴·브리지의 장면·정서·행동이 이어지는가? 서로 관계없는 비유를 나열해 내용이 흐려지거나, 나/너/우리의 전환이 맥락 없이 일어나지는 않는가? |
| 용어·비유 | 전문용어·추상어·억지 조어가 곡의 맥락에 필요한가? 멋을 위해 고른 단어가 감정을 가리거나 다른 뜻으로 읽히게 하는가? |
| 가창 문구 | 한국어로 읽었을 때 어순·호흡이 무리 없는가? 음절 수·운율을 맞추느라 문장을 비틀지 않았는가? 실제 가창 가능성과 정확도는 생성 후 검증과 구분한다. |
| 제목과 후렴 | 제목뿐 아니라 후렴·브리지·아웃트로에 남은 같은 표현도 확인했는가? 반복되는 문제 구절은 모든 등장 위치를 점검했는가? |

**뜻을 설명할 수 있는 것과 한국어로 자연스럽게 읽히는 것은 다르다.** 제목·문장을 먼저 해설 없이 읽고, 이어 원요청과 실제 가사의 구체적인 감정·장면을 근거로 판단한다. 검수자가 새 세계관이나 디지털 이미지를 덧붙여 어색한 조합을 정당화하지 않는다. 신스팝 같은 장르명만으로 「반짝의 규칙」의 명사화나 「자정의 신호」의 추상성이 자연스러워지는 것은 아니다.

AI의 미확정 초안에서 표현이 낯설거나 의미가 멀리 돌아가면, 같은 감정을 전하는 자연스러운 대안과 비교한다. 예를 들어 자기 기준을 찾는 초안의 「반짝의 규칙」은 「내 박자로」, 늦은 밤 안부를 나누는 초안의 「자정의 신호를 따라서」는 「네가 보낸 말 한마디에」처럼 구체화할 수 있다. 자연스러운 안과 실험적인 안이 모두 가능하고 실험적 표현을 원하는 근거가 없다면 자연스러운 안을 기본으로 삼는다.

이 예시는 금칙어 목록이 아니다. 원요청에 명시된 SF 서사의 「궤도 밖」처럼 의도와 맥락이 뒷받침하는 비유·말투·방언은 보존한다. 사용자 제공·승인 원문은 아래 수정 권한을 먼저 적용하며, 단순 취향 차이를 수정 필수 문제로 올리지 않는다.

전체 가사를 검수할 때는 주제·화자/대상·정서 또는 사건의 흐름을 짧게 정리하고 실제 구절로 뒷받침한다. 모든 곡에 줄거리를 강제하지는 않는다. 제목 변경 이력이나 `concept`·`hook`이 있으면 참고하되, 과거 AI 메타데이터가 현재 사용자 지시나 승인된 제목을 덮지 않게 한다. 자료가 없다는 이유로 제목만의 검토를 막지 않는다.

**한국어 내용의 자연스러움과 음원의 전달 충실도는 별도 판정이다.** 어색한 원문을 ASR가 그대로 전사해도 자연스러움이 통과한 것은 아니며, 자연스러운 수정 가사가 전사와 다르면 가창 반영은 미확인이다. 사용자가 원문 그대로의 생성을 고집한 경우에도 언어상 제안과 전달 결과를 나눠 보고하고 승인 원문은 유지한다.

### 수정과 통과 기준

1. AI가 작성한 미확정 초안은 발견한 어법·의미·표현 문제를 작성 범위 안에서 보완한 뒤 제시한다. 사용자가 제공하거나 이미 승인한 제목·가사는 [원문 보존 규칙](#preserve-input)에 따라 **원문 → 수정안 → 이유 → 적용 여부**를 제안하며, 어색하다는 판단만으로 자동 변경하지 않는다. 전체 자동 위임도 별도 제공 원문을 바꿀 권한으로 확대하지 않는다.
2. 부분 수정을 요청받으면 지정한 제목·구절과 그 반복 위치만 다룬다. 변경 줄과 횟수를 대조하고 나머지 가사·스타일·의미를 보존한다. 범위 밖에서 발견한 문제는 미적용 제안으로 분리한다. 제목만 변경해서 후렴의 어색한 표현도 고쳐졌다고 판단하지 않는다.
3. 수정 후 요청 범위의 제목·가사를 다시 읽어 문맥·화자·감정·운율을 확인한다. 전체 가사가 제공된 경우 전체 문맥을 대조하고, 제목만의 검토나 연주곡에는 없는 가사를 요구하지 않는다. 최종 전달본이 정리 과정이나 후속 편집으로 바뀌면 바뀐 부분과 연결 문맥을 다시 검수한다. 이미 승인된 의미의 변경은 [재검토 기준](#approval)을 따른다.
4. 검수 결과에 **제목 판정, 가사 판정, 문제 위치·원문·수정안·이유·적용 여부, 남은 문제, 독립/자체 검수 여부**를 남긴다. 문제가 없으면 변경 없음과 판단 근거를 적는다. 판정은 `검토 완료 / 보완 필요 / 원문 보존·제안만 / 확인 불가 / 해당 없음`으로 구분한다. 적용 대상인 AI 한국어 초안에 명확한 표현 문제가 남아 있거나 검수를 하지 못했으면 완료로 표시하거나 생성에 제출하지 않는다. 연주곡의 가사 없음·비한국어 항목의 해당 없음은 입력 누락이나 생성 차단 사유가 아니다. 제공 원문 그대로의 실행은 기존 승인 범위를 따르며 취향상 제안 때문에 재승인을 요구하지 않는다.

별도 에이전트를 사용할 수 있으면 [검수 역할](../prompts/ace-review.md)에 사용자 원요청·원문/초안 구분·수정 허용 범위와 요청 범위의 제목·가사 또는 가사 없음·제공된 스타일을 전달해 독립 검수한다. 없으면 작성 후 별도 검수 단계에서 같은 기준으로 자체 검수하고 그 사실을 밝힌다. 검수자는 원문을 덮어쓰지 않고 수정안을 반환하며, 작성자가 허용된 수정만 반영하고 재검수한다.

이 단계는 AI의 언어·문맥 판단이다. `lyrics:clean`, `lyrics:check`, `prompt:compose`의 통과나 문자 수·맞춤법 검사만으로 한국어 자연스러움 검수를 대체하지 않는다. 검토 모드와 전체 자동 모드 모두 생성 전에 수행하며, 실제 가창·음질을 검증한 것으로 보고하지 않는다.

<a id="validation"></a>

## 생성 전 기술 검증

검토 모드와 자동 모드 모두 다음을 확인한다.

단순히 “가사·프롬프트 초안만” 요청한 경우는 문서에 따른 태그·의미·분량·상충 지시의 정적 점검까지 하고, 실제로 실행하지 않은 CLI 검증은 미실행으로 표시한다. 초안만을 위해 서비스를 시작하지 않는다. 실행 가능한 JSON과 생성 준비까지 요청했거나 실제 생성으로 넘어갈 때 아래 도구 점검을 완료한다.

1. 사용자가 선택한 엔진과 실제 입력 JSON을 대조하고 해당 공개 입력 계약을 읽는다. ACE 입력은 [ACE 적용 가이드](ace-prompt-guide.md)와 필요한 [공식 원문](vendor/ace-step-1.5/README.md), YuE 계열은 [YuE 제작 가이드](yue-prompt-guide.md)와 해당 [고정 공식·MLX 원문](vendor/yue2/README.md)을 따른다. Apple Silicon의 운영 조건은 [YuE2 MLX 안내](yue-mlx.md)로 확인한다. 가사가 있는 곡의 태그는 [구간 태그 가이드](lyrics-tags.md)로 확인한다.
2. 요청의 장르·언어·보컬·길이·곡 수·가사 보존 조건을 맞춘다. 프롬프트의 악기·감정과 가사 전개가 충돌하지 않도록 한다.
3. 가사가 있으면 실제 경로의 `lyrics:clean` 전후를 비교해 태그 변환·삭제·가사 손실 여부를 확인하고, `lyrics:check`로 분량을 점검한다. 연주곡에는 가사·후렴을 요구하지 않는다. 정리 결과에서 의미가 바뀌면 검토 전에 수정한다.
4. Road Music CLI의 ACE·YuE·`yue-mlx`는 모두 공통 스타일 조합을 거친다. `prompt:compose`에 실제 생성과 같은 `genre`·악기·BPM·정리 가사·연주곡 여부를 넣어 최종 style과 notes를 확인한다. `parts.genre`가 있으면 이를, 없으면 원래 `style`을 `genre`로 옮기는 [매핑 방법](ace-prompt-guide.md#limits)을 따른다. 이 조합 절차와 ACE의 문자 수 제한은 별개다. 생성 요청에는 조합기의 notes가 보존되지 않을 수 있으므로 스키마나 요청 성공만으로 원문 보존을 확인했다고 판단하지 않는다. 삭제·중복 제거·악기/BPM 추가로 승인된 의미가 달라지면 원문과 전달본의 차이를 제시하고 해당 부분만 재검토하며, 해결 전에는 생성에 제출하지 않는다. 비교용 외부 런타임은 자체 공개 입력 계약과 실제 전달본을 대조한다.
5. 실행 버전 `schema`의 필드·범위, 대상 엔진의 입력 한계, 설치 상태와 실제 파일 경로를 확인한다. caption 512자·정리 가사 4,096자는 기본 Road Music ACE 경로에만 적용하며, 다른 엔진의 원문을 이 한계로 자르거나 거절하지 않는다. 직접 조절할 수 없는 옵션은 JSON에 넣지 않는다.

이 검증은 음원을 듣기 전의 입력 검사다. `lyrics:check` 통과를 가창·음질·저작권 검증이라고 표현하지 않는다. 정확한 원문 보존이 요청됐는데 길이를 넘으면 조용히 잘라내지 않는다.

<a id="proposal"></a>

## 요청자에게 보여줄 검토안

기술 검증이 끝난 **실제 생성 가능한 안**을 제시한다. 먼저 허락을 받고 나서 초안을 쓰는 방식으로 불필요하게 대화를 나누지 않는다.

| 항목 | 포함할 내용 |
| --- | --- |
| 곡 사양 | 제목·장르·보컬·언어·길이·BPM·악기·곡 수 |
| 가사 | 실제 전달할 전체 가사와 구간 태그. 연주곡은 가사 없음 표시 |
| 한국어 검수 | 제목·가사 판정, 문제 위치와 수정 전후·이유·적용 여부, 남은 문제, 독립/자체 검수 여부 |
| 프롬프트 | 최종 caption과 생성에 사용할 원래 `style` 또는 `parts.genre` |
| 옵션 | 실행 가능한 JSON. 전용 기능인지 모델에 요청하는 태그인지 구분 |
| 검증 | 태그 정리 결과, 최종 caption·가사 문자 수, 지원 범위 확인 |
| 근거 | 참고한 공식 문서 절, 장르 예시, 리서치 URL·날짜와 선택 이유 |

마지막에 “이 가사·프롬프트·옵션으로 생성할까요? 수정할 부분이 있으면 알려주세요.”라고 한 번 묻고 기다린다. 승인 전에는 `song:generate`·새 입력으로의 렌더·생성 재시도를 제출하지 않는다. 조회·가사 정리·프롬프트 조합은 계속할 수 있다.

기다리는 이유는 이 문서의 요청자 검토 규칙이다. 사용자에게는 “기본 검토 절차에 따라 생성 전 확인을 받습니다”라고 짧게 설명한다. 시간 경과나 무응답은 승인이 아니다.

<a id="approval"></a>

## 승인 후 실행

승인된 가사·스타일·핵심 옵션을 유지해 요청한 곡 수만 생성한다. 같은 안으로의 기술적 재검증, 이미 보여준 정리 결과 적용, 기본 seed 선택 등으로 재승인을 요구하지 않는다. 다음은 구분한다.

- **사용자가 구체적으로 요청한 수정과 생성:** “가사를 이렇게 바꾸고 바로 생성해줘” 또는 기존 곡의 가사 보완과 새 음원 재제작까지 명시한 요청이면 수정안을 검증한 뒤 실행할 수 있다. `바로/즉시`라는 특정 단어를 필수로 요구하지 않고 대화 맥락·기존 위임·실제 수정 범위를 확인한다. “가사만 다시 써줘”나 의미가 불명확한 재제작 언급을 새 음원 생성 권한으로 확대하지 않는다.
- **수정만 요청:** 기본 검토 모드에서 “후렴을 바꿔줘”라면 수정 가사·프롬프트를 제시하고, 생성하라는 지시가 없다면 자동 제출하지 않는다. 같은 작업의 전체 자동 위임이 여전히 유효하면 그 범위에서 진행하되, “초안만”·“먼저 검토” 같은 새 제한을 우선한다.
- **AI가 의미를 바꾸는 수정:** 승인 후 AI 판단으로 가사·장르·보컬·길이·곡 수·핵심 편성을 바꾸려면 변경안을 다시 검토받는다. 해당 변경까지 자동 위임받았다면 그 범위에서 진행한다.
- **오류·재시도:** `uncertain:true`는 먼저 실행 여부를 조회한다. 실패가 확인돼도 기존 승인 수량과 재시도 권한을 넘어 추가 생성하지 않는다.

설치 검증용 시험곡도 이 규칙을 적용한다. CLI 연결 점검 자체에는 새 곡이 필요하지 않다. 기존 작업 이어 만들기는 승인된 저장 입력을 그대로 쓰고 새 작사·스타일 변경이 없다면 같은 내용으로 재승인을 요구하지 않는다.

<a id="retry-value"></a>

## 재제작의 효율과 최선의 방법 추천

기존 곡의 추가 후보·부분 수정·재제작을 제안하기 전에 **사용자의 목표를 가장 적은 손실과 비용으로 달성할 방법**을 고른다. 어려움 자체를 포기 사유로 삼지는 않되, 더 생성할 수 있다는 이유로 계속 생성하도록 권하지 않는다. 같은 곡·문제의 이전 시도와 회귀도 함께 읽으며, 새 메시지나 작은 음표 변경을 이유로 실패 이력을 초기화하지 않는다.

### 재시도할 근거와 멈출 근거

- 입력 누락·잘림·잘못된 악보·실행 실패처럼 **확인된 기술 원인**이 있고 지원되는 수정으로 목표를 달성할 수 있으면 해당 원인부터 바로잡는다. 처음 생긴 기술 오류와 반복된 모델·전사 불안정을 같은 이유로 포기하지 않는다. `uncertain:true` 처리·안전 경계·기존 생성 권한은 그대로 적용한다.
- **ASR만의 불일치·문맥 충돌·직접 청취 미실행**은 실제 오발음의 확정 증거가 아니다. 원문이 정상 전달됐다면 전사 문자열 100%를 맞추기 위한 개사·악보 변경·전곡 재생성을 기본 추천으로 삼지 않는다. 가능한 범위의 판별 검사를 우선하고, 도구가 없으면 미확인으로 남긴다. 새 판별 근거 없이 문맥 길이·추출 범위를 계속 바꿔 정답 같은 전사가 나올 때까지 탐색하지 않는다.
- 반복 회귀나 전체 목표의 순이득 없는 결과가 쌓였고, 추가 시도를 정당화할 새로 확인한 원인·지원되는 해결 수단도 없다면 **추가 전곡 재제작은 비효율적이라고 설명하고 추천을 멈춘다.** 같은 방식의 작은 변형, 새 ABC·CFG·seed 교체를 새 해결책처럼 이어 붙이지 않는다. 재계획도 이 판단을 우회하는 재시도가 아니다. 모든 곡에 동일한 횟수 상한을 강제하지 않고 실제 이력·목표·비용으로 판단한다.

<a id="micro-pronunciation"></a>

### 한 음·특정 발음의 미세 교정

입력 전달은 정상이고 한 음절·받침·조사·어미의 전달만 문제인데, 현재 지원 경로가 전곡 재생성뿐이고 기존 좋은 구간의 유지가 중요하다면 **미세 발음 교정을 위한 전곡 재생성을 기본 추천하지 않는다.** 바꾸는 음표 수가 아니라 실제로 다시 생성되는 범위와 비용·회귀 위험으로 판단한다. 한국어 음절과 음표를 직접 묶거나 구간을 고정하는 기능이 확인되지 않았다면, 음가·피치 수정 가설을 해당 발음만 고치는 지원 기능처럼 설명하지 않는다.

음표 하나의 길이·피치·공격음을 달리하거나 새 ABC로 바꾼다는 사실 자체는 새 기술 원인이 확인됐다는 근거가 아니다. 같은 미세 교정 목표를 `한 음만`, `한 마디만`, `더 안정적인 후보 기준`으로 좁혀 다시 제안해도 기존 누적 시도로 판단한다. 반복을 다시 권하려면 이전 실패와 다른 확인 가능한 근거와 지원 방법이 필요하며, 아직 검증되지 않은 음절 대응 추정만으로 효율 판단을 갱신하지 않는다. 확인된 입력·잘림·악보 기술 오류의 수정과 사용자가 명시한 한정 실험은 아래 규칙대로 구분한다.

### 가장 나은 현재 방법을 먼저 제안

최신 후보보다 **전체 목표와 보존 조건을 가장 잘 충족한 안정 후보**를 기준으로, 현재 권장 방법 하나와 이유·남은 불확실성을 먼저 제시한다. 청취하지 않았다면 전사상 안정성과 실제 음질·발음 우열을 구분하고, 안정 후보를 남긴다는 이유로 필수 구절의 미확인을 통과 처리하지 않는다.

추가 생성보다 기존 후보 보존·비교·검수 판정 보류가 유리하면 그것을 추천한다. 실제로 확인된 오류를 국소적으로 고칠 지원 기능이 있다면 그 방법을 우선 검토하되, 현재 엔진·공개 CLI가 그 기능과 보존 요구를 충족하는지 확인한다. 미지원 구간 고정·보컬 재녹음·편집을 지금 실행 가능한 기능으로 안내하거나, 다른 모델의 한국어 정확도를 근거 없이 보장하지 않는다. 다른 엔진·새 설치·외부 전송·원문 변경이 필요한 대안은 제안과 실행 권한을 구분한다.

알 수 있는 생성 시간·실패/복구 비용·회귀 위험은 판단에 사용하되 수치를 꾸며내지 않는다. 권장안이 왜 다음 전곡 재생성보다 나은지 짧게 설명한다. 가능한 방법을 길게 나열하거나 다시 만들어 보자는 제안만 남기지 않는다.

### 명시한 실험과 결과 판정

사용자가 한계를 알고도 특정한 한정 실험을 명시하면 그 범위에서 실행할 수 있다. `한 번만 더`는 실행 횟수의 제한일 수 있지만 성공 근거나 효율적인 방법이라는 판단은 아니다. 권장 여부와 실행 권한을 구분하고, 이미 그렇게 승인된 요청에는 같은 승인을 다시 묻지 않는다. 실패 결과나 새로 보인 ASR 차이를 후속 후보·새 가설 실험의 자동 승인으로 확대하지 않는다. 사용자가 추천·검수만 요청했거나 추가 재생성을 원하지 않으면 생성하지 않는다. 명시한 선호·목표를 조용히 다른 모델이나 임의 개사로 대체하지 않는다.

실행한 후보는 목표 구절뿐 아니라 **기존 안정 후보의 개선 구간과 전체 보존 조건**을 함께 비교한다. 전체적으로 악화됐으면 새 후보를 권장하지 않고 안정 후보·원본·실패 기록을 보존한다. 서로 다른 후보의 성공 구절을 합쳐 한 곡의 통과로 보고하지 않는다. 결과에는 권장 방법·근거·남은 문제와 실제 실행/미실행 범위를 간결하게 남긴다.

`안정 후보 유지·추가 재제작 비추천·남은 발음 미확인`도 추천·검수 작업의 정상 종료 결론이다. 이를 다시 생성해야 할 미완료 단계로 자동 되돌리지 않는다. 검수를 마쳤다는 뜻과 음원의 전곡 가사·발음이 통과했다는 뜻은 구분한다.

<a id="delivery"></a>

YuE MLX 가사 수정·재생성은 [악보 선택](yue-prompt-guide.md#score-choice)을 적용한다. 가사 전달 우선과 원곡 선율 보존을 구분하고 기존 ABC 재사용을 자동 기본으로 삼지 않는다. 완성본 검수를 요청받았거나 생성 결과를 보고할 때는 [전곡·구간 가사 검수](yue-prompt-guide.md#lyrics-verification)로 원문/전달본·새 악보/재사용·파일 기술 검사·자동 전사·실제 청취를 구분한다. 전사 불일치만으로 승인 범위 밖을 개사하거나 재생성을 반복하지 않는다.

## 자동 모드의 결과 자료

자동 모드에서는 승인 질문으로 멈추지 않는다. 생성 전에 자체 입력 검증을 끝내고, 완료 후 다음 자료를 제공한다. 검토 모드로 승인받아 생성한 경우에도 같은 자료가 유용하다.

| 자료 | 제공 범위 |
| --- | --- |
| 음악 | 실제 오디오 절대 경로와 파일 링크, 지원되는 채팅에서는 오디오 첨부 |
| 가사 | 실제 전달된 전체 가사. 제목·작사안과 생성된 가창이 다를 수 있음은 청취 결과와 구분 |
| 프롬프트·설정 | 실제 caption, 원래 입력 JSON, 기록 가능한 seed·엔진·길이·작업 결과 |
| 참고 자료 | 로컬 공식 문서 경로와 해당 절, 장르 레시피. 외부 조사는 URL·게시/집계일·확인일 |
| 선택 이유 | 자료에서 어떤 사실을 확인했고 어떤 창작 판단으로 보컬·악기·구조를 골랐는지 |
| 한국어 검수 | 최종 제목·가사의 판정, 수정 전후와 이유·적용 여부, 원문 보존 또는 미적용 제안, 남은 문제 |
| 검증과 한계 | 입력 검사·파일 길이·포맷과 청취 여부. 측정하지 않은 BPM·조성·가창 정확도는 단정하지 않음 |

예를 들어 “공식 가사 구조 절을 참고해 Verse→Pre-Chorus→Chorus로 구성했고, 트로트 레시피에서 아코디언과 셔플 리듬을 골랐다”처럼 구체적으로 적는다. 읽지 않은 문서를 출처로 나열하거나 프롬프트만으로 모델을 100% 제어했다고 표현하지 않는다. 별도 결과 파일 저장은 요청되거나 작업에 필요한 범위에서 수행하며 기존 파일을 덮어쓰지 않는다.

<a id="examples"></a>

## 복사해서 요청하기

기본 검토:

```text
여성 보컬 락발라드 1곡을 준비해줘. 한국어 가사, 150초, 피아노와 기타 중심으로.
ACE 공식 가이드와 태그 가이드를 적용해 가사·프롬프트·옵션을 검증한 뒤 먼저 보여줘.
```

자동 생성:

```text
가사와 프롬프트까지 모두 자동으로 정해서 한국어 트로트 1곡을 생성해줘.
ACE 공식 가이드를 적용하고 요청자 검토는 생략해줘.
완료 후 음악·가사·최종 프롬프트·옵션과 참고 자료·선택 이유를 제공해줘.
```

기존 검토안 승인:

```text
방금 보여준 가사와 프롬프트, 옵션 그대로 1곡 생성해줘.
```

# HTML Codex 대화 전문·이력 검수

2026-10-20, macOS 로컬 소스와 Codex CLI 0.163.0 기준. [설계와 공식 근거](studio-codex-chat-design.md).

## 구현 결과

제작실과 음악 상세의 공통 대화창에서 같은 Codex 대화에 질문하고, 저장된 사용자 요청·공개 Codex 답변 전문과 이전 이력을 확인한다. 최신 이력 자동 확인, 이전 대화 더 보기, 메시지 원문 복사와 복사 거절 시 수동 복사를 제공한다. 기존 음악·가사·영상의 검토/제작 요청은 구간·미디어 SHA·수정 가사·보존 조건을 유지한다.

송신은 기존 공식 `codex queue`를 사용한다. 일반 대화는 `chat/review`만 허용하고 생성·설치·파일 변경을 지시하지 않는다. 응답 조회는 공개 `studio:conversation:history`와 인증된 `/api/agent/history`를 통해 연결된 프로젝트의 threadId만 읽는다. 새 RPC reader는 `initialize → thread/read → thread/turns/list(itemsView:full)`만 호출한다. 대화 재개·모델 실행·내부 이력 DB 직접 접근은 없다.

## 실제 설치 연결 확인

현재 연결된 Codex 대화의 공개 CLI 이력 조회가 성공했다. 실제 음악 상세 HTML에서도 최신 5개 turn과 사용자·assistant 전문을 표시했고, 이전 대화 더 보기로 총 11개 turn을 확인했다. 4,000자를 넘는 답변도 생략하지 않았다. 이 실기에서는 실제 queue 제출·turn 시작 없이 **읽기만** 수행했다.

기존 선택과 초안을 보관하고 제작실 HTTP 서버만 공개 `motion:studio`로 갱신했다. 음악 생성 서비스는 중단하지 않았다. 원래 음악 상세로 복귀했으며 결과 대화창을 열어 둔다.

기존 원본 폴더 36개 파일의 SHA-256이 보관한 원장과 모두 일치했다. v3 음원 SHA-256도 기존 `3c4ae4b545774b080e7c863bc4d2762bb0eccf6a4346ab328c845b5702e7fb45`와 동일했다.

## 수정 요청 입력창 접근성 보완

2026-10-20, 사용자가 입력창을 찾기 어렵다는 의견에 따라 공통 입력 폼을 음악 상세와 제작실 **상단**으로 이동했다. 기존에는 상세 페이지의 폼이 제작 기록 안쪽, 요약 화면 아래 약 4,000px 지점에 있었다. 입력 폼과 저장된 대화 이력을 분리해, 긴 과거 이력이 완성 파일 재생 영역을 밀어내지 않게 했다.

- 상단 **음원·가사·영상 수정 요청**에서 대상·요청 방식과 큰 입력칸을 바로 확인한다.
- 음원·가사·영상 영역의 바로가기는 해당 대상을 선택하고 같은 프롬프트에 포커스한다. 가사 수정은 읽기 전용 원가사와 수정 가사도 펼친다.
- 스크롤 중에는 고정 **수정 요청 입력** 버튼으로 복귀한다. Enter 키로 눌러도 입력칸에 커서가 놓인다.
- **답변·대화 이력 보기**는 기존 제작 기록의 저장된 대화로 이동한다. 요청 ID·수신/완료 상태와 공개 CLI 전송 경계는 그대로다.

Ego의 실제 상세에서 세 대상 간 전환·키보드 포커스·원가사 읽기 전용·작성 중 프롬프트와 수정 가사의 새로고침 보존을 확인했다. 입력 폼은 한 개이며 이력은 별도 기록 호스트에 남는다. 320×850 화면에서 고정 버튼을 누르면 입력칸 전체가 353.25~497.25px에 보이고 커서가 놓였다. 가로 넘침은 없고 Paperlogy 16px을 사용한다. 제작실(`/`)에서도 폼이 음악 설정보다 앞에 있고 같은 버튼이 동작했다.

이전 검증용 `motion:studio` 서버가 외부 CLI의 1시간 제한으로 종료된 것을 확인했다. 기존 초안을 보존하고 공개 `service:start`의 정상 제작실 시작 경로로 다시 연결했다. 음악 서비스 PID `65525`는 유지됐고, 새 주소에 기존 선택·초안을 복원했다. 최종 화면에는 검수용 문구를 남기지 않았다.

전체 `npm test` **402/402**, 마지막 UI 보완 뒤 agent CLI/Python/UI 회귀 **6/6**, 변경 JS 구문 검사, 정본/미러 7개 파일 일치와 독립 코드 검수를 통과했다. 제품 소스 변경은 공유 HTML·JS·CSS·가이드와 UI 회귀에 한정했다. 새 요청 등록은 **0건**이며, 기존 두 요청 ID만 남아 있음을 확인했다. 음원·영상 생성·기존 완성 영상 재렌더는 하지 않았다. 실제 휴대폰 키보드는 검증하지 않았으며 320px 브라우저 화면으로 검사했다.

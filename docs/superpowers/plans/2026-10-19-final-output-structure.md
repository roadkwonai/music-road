# 완성본 전용 Output과 SQLite 버전 이력

사용자 승인: 기존 미연결/legacy 자료는 테스트 이력으로 폐기 가능. 현재 프로그램/모델/원음/실제 등록 완성본은 새 위치에 검증 보존하고 나머지 이전 제작 구조를 정리한다. 활성 작업은 종료시키지 않고 idle 여부를 공개 상태로 확인한다.

## 디렉터리 계약
- `Output/<음악명--sourceSHA12>/<프로젝트명--projectID12>/<YYYYMMDD-HHMMSS[-충돌번호]>/`: 검증된 음원·영상·가사·자막·최종 스토리보드만. JSON 이력/캐시/중간본/실행환경은 두지 않는다.
- `.roadmusic/work/<musicId>/<projectId>/`: 편집 입력·현재 제작 설정·렌더와 재개 자료. 완료 후 관리 정책에 따라 캐시 정리.
- `.roadmusic/history.sqlite3`: 프로젝트·버전·파일 해시/크기·요청 스냅샷·변경 사유. 메타데이터만 저장하며 미디어 BLOB은 넣지 않는다.
- 모델·공용 runtime은 앱 데이터의 engines/runtime에 보존한다. 테스트 폴더의 모델/venv/symlink를 현재 프로그램이 참조하면 검증 이동을 먼저 완료한다.

## 동작
1. 전체 스캔/의존성 점검→확정 완성본 canonical 게시/원음 SHA 검증→라이브러리 경로 갱신→legacy 폐기 계획→일회 확인 실행→재스캔/완성본/모델 검증.
2. 새 제작은 Output 내부를 작업 루트로 사용하지 않는다. 원래 요청이 Output 아래면 hidden work로 안내/변환한 실제 경로를 반환해 후속 명령은 그 경로를 사용한다. 명시 파일 덮어쓰기는 하지 않는다.
3. 게시 성공 때 시간 버전을 원자 생성하고 이전 같은 프로젝트 스냅샷/파일과 diff한다. 같은 내용 재게시로 중복 버전을 만들지 않는다. 과거 수정 사유를 추측하지 않고 미기록으로 표시한다.
4. 기존 WorkLibrary JSON은 현재 결과 목록의 호환 투영으로 유지한다. SQLite는 버전/diff 기준이다. 소스/최종 경로가 변경되면 검증 후 투영과 project.media를 갱신한다.
5. 공개 API: storage:versions {groupId,projectId?,limit?,offset?}, storage:version-diff {fromId,toId}; HTTP /api/works/<groupId>/versions, /api/works/<groupId>/version-diff?fromId=&toId=. diff는 같은 음악/프로젝트만 허용.
6. HTML 작업물 상세에 버전·변경 내역을 두고 프로젝트 필터/초단위 시각/사유/설정 및 텍스트 diff/파일 added/removed/changed를 표시한다. 저장공간 화면은 실제 디스크 used/free와 작업폴더 음악/모델/프로그램/기타를 별도 그래프로 표시한다.

### 화면 계약

- 디스크 막대의 분모는 디스크 전체이고, 작업 폴더 막대의 분모는 전체 스캔 할당량이다. 두 값을 같은 막대나 비율로 합치지 않는다. 전체 용량을 확인할 수 없으면 그래프 대신 확인 불가 상태를 표시한다.
- 작업 폴더 범례는 음악 그룹, 모델·프로그램, 테스트 입력, 미연결 자료와 남은 분류 미기록을 용량·비율·기호로 함께 표시한다. 390px와 다크 모드에서도 같은 텍스트 정보를 유지한다.
- 버전 목록은 API의 메타데이터만 렌더하고, 수정 사유가 없으면 `수정 사유 미기록`으로 표시한다. version-diff는 같은 프로젝트 선택일 때만 요청하며, 모든 서버 값은 `textContent`로 출력한다.

## 검증
쓰기 전 회귀를 추가하고 symlink/변경/활성 작업/동일 초 충돌/동일 내용 재게시/SQLite 실패/복사 검증/정리 실패에서 원본 보존을 검사한다. 새 의존성 없음. 독립 검수 뒤 실제 HTML과 공개 CLI로 실행하고 실제 할당/디스크 여유 변화를 보고한다.

## 검수에서 확인한 임시 등록 잔재

일부 테스트의 자식 프로세스와 HTML Session이 실제 기본 레지스트리를 사용해 이미 삭제된 임시 프로젝트 등록을 남겼다. 테스트는 전용 데이터 경로로 격리한다. 구조 정리 미리보기에는 현재 존재하지 않는 알려진 tmp/cd-playlist-input 임시 경로의 빈 등록 기록만 명시한다. 실행 때 기록 내용·부재·잠금을 재검증하고 일치하는 등록만 제거한다. 디스크 파일은 삭제하지 않는다. 폴더가 다시 생겼거나 등록·잠금이 달라졌으면 유지한다. 완료된 구조의 재실행으로 최종본/편집 설정을 다시 가져오지 않는다.

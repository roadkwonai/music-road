# 기존 모델 실생성·Showreel·저장공간 검증

기존 프로그램·모델·완성본은 유지한다. 기본 서비스의 작업 상태를 먼저 확인하고, 기존 runtime만 공유하는 격리 ROADMUSIC_DATA_DIR 프로필에서 ACE 1곡을 생성한다. 가사·프롬프트는 사용자 자동 위임에 따라 한국어 검수 및 공개 prompt/lyrics 검증 후 제출한다. 반환된 jobId를 job:wait으로 확인한다.

Showreel native 한 곡 샘플은 생성된 원음과 실제 가사·시계를 사용한다. image_gen으로 실제 장면 2장과 전용 썸네일을 생성하고 이미지 기반 네이티브 장면을 구현한다. 엔진 검사·실제 프레임·최종 디코드·오디오 레벨·브라우저 음원/영상 재생을 확인한다. 이전 절차형 전용 테스트는 최종본에서 제외한다. 임의 톤/기존 곡 재사용을 실제 AI 생성으로 표시하지 않는다.

캐시 검증은 실제 renderer lease·재개 보호·예산/완료 자동 정리를 확인한다. 게시 후 canonical Output과 SQLite 최소 이력에 최종 음원·영상·가사/자막만 보관한다. 공개 계획으로 완료한 작업 자료를 정리하고 sample 서비스·임시 프로필을 종료한다. 새 파일이 Output/중복 앱/공유 video-cache에 남지 않는지 재스캔한다.

추가 사용자 요청: 저장공간 음악별 파일에 플레이·다운로드·명시 삭제를 연결한다. 현재 원음/편집 입력/모델·프로그램·외부 원본을 보호하고, canonical 파일 선택 삭제는 사용자가 확인하는 일회 계획·버전 영향·최소 삭제 이력을 적용한다. 무반응처럼 느껴지는 버튼은 눌린 위치에 진행·결과·오류·빈 목록의 이유를 알린다.

필요한 CLI·HTML·문서·music-road-skills 관리본만 좁게 보완하고 실제 동작과 회귀로 검증한다. 배포/Release/다른 세션의 스킬 이전은 수행하지 않는다.

추가 최적화: 통합 Status의 가벼운 capability 확인을 CLI·HTML·정리 실행의 공통 기준으로 삼는다. 존재하지 않는 Git·설치 검증 자료 등은 비활성 사유를 보이고 검사하지 않는다. 일반 조회는 저장된 메타데이터를 재사용하며, Git 객체 전체 분석은 해당 기능을 명시 실행할 때만 수행한다. SQLite에 동일 상태를 중복 저장하지 않고 기존 버전·삭제 기록의 N+1 조회만 배치 처리한다.

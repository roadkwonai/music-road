# SQLite 기반 저장공간 소유권·제작 이력 관리

## 현재 문제와 범위

미연결 약 30MB의 대부분은 `.roadmusic`, `.harness`, `.omx`, `_workspace` 등 관리·검수·실행 도구 영역이다. 프로그램/도구 관리 자료를 고아 제작물로 오인하지 않도록 소유권과 용도를 기록한다. 이름만으로 삭제 권한을 만들지 않는다. 원음·모델·기존 완성본·활성 외부 세션을 보호한다.

프로필의 저장공간 레지스트리·작업물 색인·캐시 메타데이터·변경/정리 이력은 표준 Python SQLite로 관리한다. 기존 workspace `.roadmusic/history.sqlite3`는 검증된 납품 버전의 원장으로 유지한다. 프로필과 납품 작업 폴더의 경계를 유지하되 CLI/HTML에서는 하나의 음악/프로젝트 화면으로 연결한다. 새 라이브러리/서버/별도 설치는 추가하지 않는다.

제작 엔진이 사용하는 프로젝트 JSON·원가사·실제 미디어는 파일로 둔다. SQLite에는 변경 전후의 작은 메타데이터·경로·소유권·상태·통계만 저장한다. 미디어/프레임 BLOB이나 매 프레임 상세 로그는 넣지 않는다. 수정 없는 조회가 DB 갱신·전체 검사·Git 분석·VACUUM을 시작하지 않도록 한다.

## 구현 순서

1. 기존 동작과 파일 보호를 회귀 테스트로 고정한 뒤 SQLite 관리 저장소와 기존 JSON의 검증 가능한 일회 이전을 추가한다. 실패 시 원본/DB 상태를 보존하고 중복 이전하지 않는다.
2. 프로젝트 생성부터 소유 경로와 음악 연결을 등록하고 등록/정책/캐시·생성·제목/가사/음원·영상·선택·피드백 변경을 SQLite 이벤트에 기록한다. 스캔은 메타데이터를 일괄 색인하고 일반 조회는 재사용한다.
3. 관리/프로그램/도구 영역과 진짜 소유권 미확인 영역을 분리한다. 알려지지 않은 자료를 숨기거나 임의 캐시로 바꾸지 않는다. 검증된 잔재만 공개 미리보기/확인 절차로 정리한다.
4. 프로젝트·그룹 제거는 선택한 범위를 먼저 검증하고 해당 DB 이력/경로/연결도 함께 제거한다. 공유 파일·활성 작업·모델·프로그램·외부 원본을 보존하며 실패 복구와 중복 실행 방지를 확인한다.
5. HTML에 관리 분류·추적 현황·변경 이력·정리/삭제 영향, 툴팁·명시적 도움말 모달·Markdown/HTML 가이드를 연결한다. 관리 스킬 원본은 music-road-skills에서 보완한다.
6. 격리 fixture에서 생성/제목/가사/영상 변경→이력→정리→프로젝트/그룹 제거를 검증한다. 실제 환경은 소유권 색인/안전 잔재 정리만 실행하고 기존 완성 파일 해시를 보존한다. npm·Python/JavaScript 구문·HTTP·실제 Ego HTML을 검증한다.

## 성능과 완료 기준

- 알려진 소유권/경로와 최근 변경은 SQLite 인덱스로 조회하고 음악마다 전체 폴더를 반복 재탐색하지 않는다.
- 큰 전체 인벤토리는 명시 스캔 때 배치 저장한다. 변경 없는 파일의 내용 해시는 다시 계산하지 않는다. 삭제/게시 전 보호 검증은 유지한다.
- 관리/도구 폴더가 미연결 제작물로 표시되지 않는다. 실제 unknown은 용도 미확인/보호 사유를 표시하고 누락시키지 않는다.
- 프로젝트/그룹 제거 후 대응 live row·파일 색인·이력이 남지 않으며, 다른 곡/공유 원본은 유지된다.
- 최종 사용량·삭제 수·실제 디스크 여유 변화, SQL/JSON 선택 이유·검증 범위를 보고한다.

## 공식 근거

- https://www.sqlite.org/foreignkeys.html — 연결마다 외래키 활성화와 관련 자식 행의 삭제 규칙 검증.
- https://www.sqlite.org/wal.html — 짧은 트랜잭션·읽기/쓰기 동시성 및 WAL 파일 수명 고려. 조회마다 VACUUM이나 강제 checkpoint를 하지 않는다.

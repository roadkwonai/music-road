# YuE2 CLI 확장 실기 검증

[고급 제작 워크플로](yue-cli-workflow.md) · [YuE 제작 가이드](yue-prompt-guide.md) · [CLI 검수 기록](cli-qa-report.md)

2026-10-19 로컬 개발 소스에서 수행했다. 공개 CLI를 통해 M1 Ultra 64GB의 기존 YuE2-3B·YuE2-Vae·고정 MLX 런타임을 사용했다. 새 모델 다운로드나 실제 사용자 서비스 교체는 하지 않았다. 이 결과는 미배포 소스의 검증이며 M1 Max 32GB·Windows의 실측 결과가 아니다.

## 방법과 결과

여성 보컬을 요청한 한국어 록발라드와 발라드의 승인 가사·목표 180초를 유지했다. 각 장르의 8bit 시드 2개, 같은 계획의 BF16 버전, 같은 semantic/noise의 ODE16 재합성, 같은 latent의 VAE core512 재디코딩으로 비교 음원 8개를 만들었다. 원문과 재사용 source의 해시를 전후 대조했다.

시간은 제출부터 `job:wait` 완료까지의 벽시계 시간이다. 모델·파일 검사, 로딩과 출력 처리 비용을 포함한다. CER은 설치된 로컬 Whisper large-v3-turbo의 한국어 무유도 전사를 정규화한 원문과 비교한 문자 오류율이며 낮을수록 전사 일치도가 높다. 음질·음정·여성 보컬·편곡 점수가 아니다.

| 시험 | 실제 음원 길이 | 공개 CLI 완료 시간 | 가사 CER |
| --- | ---: | ---: | ---: |
| 록 8bit·시드 1 | 247.28초 | 426.82초 | 11.16% |
| 록 8bit·시드 2 | 212.28초 | 361.76초 | 20.72% |
| 발라드 8bit·시드 1 | 161.72초 | 249.49초 | 3.25% |
| 발라드 8bit·시드 2 | 251.76초 | 458.59초 | 2.85% |
| 록 BF16·시드 1 계획 재사용 | 247.00초 | 416.29초 | 10.76% |
| 발라드 BF16·시드 1 계획 재사용 | 162.84초 | 242.28초 | 4.88% |
| 록 ODE16·semantic/noise 재사용 | 247.28초 | 163.09초 | 11.95% |
| 록 core512·latent 재사용 | 247.28초 | 17.76초 | 11.16% |

8개 모두 48kHz stereo, 전체 디코딩·유한 신호·공식 ABC 구조 검사를 통과했고 ABC/semantic 잘림은 없었다. 샘플의 절댓값이 1 이상인 수는 0이었지만 일부 true peak는 반올림해 0.0dBFS였다. 이 검사만으로 청감상 왜곡이나 믹스 품질을 확정하지 않는다. 전곡 전사에 이어 같은 록 장르에서 전사 오차가 낮은 후보와 높은 후보의 문맥 60초 구간을 각각 다시 전사했다. 서로 다른 곡의 고정 시간창에 임의 원문을 대응시켜 CER을 만들지 않았다.

직접 오디오 입력은 도구가 지원하지 않아 청취 판정은 수행하지 못했다. 실제 전사의 오인식·환각 가능성을 포함해 여성 음색, 고음, 음정·리듬과 음질의 우위는 미확인이다.

## 성능 해석과 출발점

1. **일반 제작 출발점은 기존 8bit·ODE32를 유지한다.** 발라드의 두 기본 후보는 CER 2.85~3.25%였지만 실제 길이는 161.72초와 251.76초로 크게 달랐다. 시드만 바꿔도 길이·전사가 달라지므로 한 설정을 최상으로 일반화하지 않는다.
2. **승인한 semantic의 빠른 재합성에는 ODE16을 비교 후보로 쓸 수 있다.** 같은 록 원본에서 NAR 연산이 284.16초→144.67초로 약 49.1% 줄었다. CER은 11.16%→11.95%였다. 공개 완료 시간 163.09초는 ABC·semantic 재사용의 이점도 포함하므로 새 곡 전체 생성이 같은 비율로 빨라진다는 뜻은 아니다. 음질 유지 여부는 청취 후 선택한다.
3. **BF16은 비교 선택지로 유지한다.** 록 semantic 속도는 8bit 61.47→BF16 56.89 token/s였다. 록 CER의 차이는 작고 발라드 CER은 오히려 증가했다. BF16 재생성은 ABC를 재사용했으므로 총시간이 조금 짧다는 이유로 정밀도의 속도·품질 우위를 주장하지 않는다. 공식 MLX의 BF16 기본과 Road Music의 8bit 호환 기본은 구분한다.
4. **디코딩만 바꿀 때는 latent를 재사용한다.** core512의 VAE 연산 7.99초, 공개 완료 17.76초를 확인했다. 가사·선율·편곡 변경은 새 생성 또는 그에 맞는 앞 단계 실행이 필요하다.

생성·재합성 프로세스의 sampled physical footprint 최대값은 약 10.0~10.5GiB, 프로세스 자체 peak 기록은 약 10.6~10.8GiB였다. 디코딩 전용은 각각 약 5.3/5.9GiB였다. 메모리 압력은 정상이고 시험 중 새 swap-out은 0이었다. 시작 시 존재하던 시스템 swap을 이번 생성의 실패로 세지 않았다. 32GB Mac의 메모리 적합성을 추정하는 근거이며 다른 앱·OS·GPU 차이를 없애지 않는다. M1 Max의 실제 속도는 미측정이다.

첫 실행은 공유 모델 symlink를 upstream이 거부해 약 0.7초 만에 실패했다. 검증된 모델/VAE를 canonical 경로로 전달하도록 수정하고 같은 요청을 한 번 재시도했다. 실패·복구 기록은 성공 시간과 별도로 보존했다. 4bit 변환물은 미설치라 생성 시험과 자동 변환을 하지 않았다.

## 기능·보존 검증

- 별도 계획 작업에서 고급 옵션 16개의 명시값을 실제 native plan과 모두 대조했다. 최대 시드 `9223372036854775807`은 정수 값과 메타데이터 문자열에서 정확히 유지됐다. 이 작업의 실험 숫자를 품질 프리셋으로 승격하지 않았다.
- 공개 `song:replay`→`song:cancel`→`job:wait`에서 취소 terminal 이벤트 1회, 자식 프로세스 회수, 원본 계획 해시 보존을 확인했다. 테스트 서비스만 격리 프로필에서 재시작·종료했다.
- plan 재사용의 ABC IDs/prefix, synthesize 재사용의 semantic/noise, decode 재사용의 latent와 source 불변을 검사했다. 완료 source는 원생 artifact 검사로 설정 무결성을 검증한다.
- 전체 `npm test` 307/307, 변경 JavaScript 구문, Python 컴파일, 스킬 validator와 독립 코드 검수를 통과했다. CLI ZIP을 실제 추출해 신규 파일·큰 seed 사전검사·공식 ABC 검사를 실행했다.
- 전체 회귀에서 설치 명령이 `exit` 직후 stdout을 확정하는 경합을 재현했다. `close`까지 수집하도록 한 줄을 고치고 회귀를 추가했다. 관련 16개 검사와 전체 검사를 다시 통과했다.

로컬 원본 증거는 `Output/yue-cli-expansion-20261019/`의 입력·공개 명령 응답·8개 음원·전사·자원 기록·해시에 보존했다. 대형 음원과 모델은 문서·CLI 배포물에 포함하지 않는다. Windows GPU, 실제 SheetSage2/MERT 전사와 실제 LoRA 음원 추론은 미검증이며 fixture·옵션 전달 검증과 구분한다.

실행 코드의 공식 태그는 `yue2-v0.1.6`, MLX 커밋은 `c5b5a8190f78c74aa671a4caa19dae8b8e04b3d8`, 모델/VAE 리비전은 [보관본](vendor/yue2/README.md)에 기록했다. 공식 저장소의 현재 main은 YuE2이고 원래 YuE는 `YuE-v1`로 분리돼 있다. 고정판 이후 문서·연주곡 스킬·라이선스 변화는 [현재 자료](vendor/yue2/current/README.md)로 구분하며, 실행 기능이 자동으로 추가됐다고 판단하지 않는다.

## 매 제작 요청의 순서

1. 원요청에서 엔진·곡 수·언어·보컬·장르·길이·수정 범위를 먼저 확정한다. 사용자가 YuE MLX를 지정하면 `engine:"yue-mlx"`를 유지한다. 미설치를 이유로 ACE로 바꾸거나 모델을 다운로드하지 않는다. 미지정 엔진만 공개 schema와 환경에 맞는 선택을 가정값으로 제시한다.
2. 이 가이드와 해당 작업의 고정 원문을 읽고, 기본 검토/제공안 승인/전체 자동 위임을 [검토 규칙](music-review.md)으로 구분한다. 제목·가사 표현만 검토하는 요청에는 엔진 조회·설치·생성 자료를 요구하지 않는다.
3. 한국어 제목 또는 가사가 있으면 [한국어 검수](music-review.md#korean-review)를 해당 항목에 수행한다. AI 초안의 어색한 단어 결합·문장·후렴은 자연스러운 대안으로 보완하고 다시 읽는다. 제공·승인 원문과 부분 수정 범위는 보존한다. 연주곡의 가사·비한국어 항목은 해당 없음이다.
4. 생성 준비에는 `app:state`, `engines:list`, `projects:list`, `songs:list`, 실행 버전 `schema`와 실제 프로필을 확인한다. 이전 조회가 다른 프로필에서 이뤄졌다면 그 결과로 설치 상태를 대신하지 않는다. 생성/렌더 중인 기존 작업을 종료하거나 기본 앱을 재시작하지 않는다.
5. 원래 style·lyrics·parts와 공통 CLI 정리·조합 결과를 대조한다. ACE뿐 아니라 YuE도 `prompt:compose`에 실제 생성과 같은 style/parts·정리 가사·연주곡 값을 매핑해 최종 style과 notes를 확인한다. 긴 문장이 삭제될 수 있으므로 스키마 통과만으로 승인 원문이 그대로 전달된다고 판단하지 않는다. [태그 가이드](lyrics-tags.md)는 Road Music의 전처리 계약이며 원생 YuE의 태그 보장표가 아니다. 의미·핵심 태그가 바뀌거나 잘림이 예상되면 조용히 삭제하지 않는다. 최종 YuE 입력을 ACE의 512/4,096자에 맞춰 자르지 않는다.
6. 아래 모드와 실제 공개 필드로 입력 JSON을 준비하고 제목·가사 판정, 전체 전달본, style·옵션·근거를 보여준다. 생성까지 명시적으로 전부 자동 위임받은 경우에는 요청자 검토만 생략하고 검수는 수행한다. 문서 조사나 스킬 업데이트 요청에 음악 생성을 추가하지 않는다.
7. 추가 재제작은 먼저 [효율·중단·추천 기준](music-review.md#retry-value)으로 판단한다. 전사만의 불일치와 반복 회귀에 새 전곡 생성을 자동 권하지 않는다. 새 곡, 유효한 재제작 또는 한계를 알고 명시한 실험은 승인/위임 범위에서 1곡 요청을 `count:1`로 제출한다. `song:generate`가 반환한 `jobId`를 같은 프로필의 `job:wait`으로 확인한다. `uncertain:true`면 `service:status`, `queue:list`, `songs:list` 등으로 실행 여부부터 확인하고 재제출하지 않는다.
8. 입력·모델/VAE·실효 설정·seed·실제 파일·길이·truncation·시도/실패/복구 시간을 남긴다. 마지막 절의 검수 범위를 구분해 보고한다. 새 요청·새 버전은 새 출력 경로에 저장하고 기존 곡은 보존한다.

## 스타일·제목·한국어 가사

공식 [generation](vendor/yue2/official/docs/generation.md)은 style에 장르·주악기·보컬 성격·언어·템포를, lyrics에 실제 부를 문장과 `[Verse]`, `[Chorus]` 같은 섹션을 쓰도록 안내한다. 제어 문장·설정값을 가사에 섞지 않는다. 사용자 원문을 먼저 보존하고 가사 정리본은 별도로 비교한다.

- 스타일은 중요한 음악적 방향부터 간결하게 작성한다. 예: `Korean traditional trot, mature solo female vocal, clear Korean phrasing, two-beat ppongjjak rhythm, accordion, brass and drums, warm and affectionate`. 이는 여성 트로트 제작 적용안이며 공식 장르별 성능 보장이 아니다.
- 제목은 사람이 읽는 곡명·파일명·메타데이터다. Road Music 워커의 원생 SongRequest에는 제목 필드가 없으므로 제목만 바꿔서 모델이 부를 후렴이 바뀐다고 가정하지 않는다.
- 한글 원문·줄바꿈·화자·감정을 유지한다. 한국어를 요청하는 style과 실제 가사를 맞추되, `language`, `vocal_language`, `phonemes`, 참조 가수 같은 미지원 필드를 만들지 않는다. 원생 `tags` 별칭도 Road Music JSON의 필드가 아니다.
- YuE-v1 README의 한국어 지원 설명과 YuE2 모델 카드의 `zh/en` 메타데이터, 로컬 한국어 제작 관찰을 구분한다. 한국어 입력을 전달할 수 있다는 사실이나 v1의 한국어 안내로 YuE2 한국어 가창·트로트 품질을 보증하지 않는다. 현재 README의 GitHub Trending 표시인 `All languages`를 음악 생성 언어 목록으로 해석하지 않는다.
- 공식 기본 지침은 Verse/Chorus 등의 구조다. v1의 섹션당 약 30초·`[intro]` 회피·stage1 CoT/ICL 체크포인트 조언을 YuE2의 필수 규칙으로 옮기지 않는다. 한국어 음절 수를 기계적으로 잘라 맞추지 않는다.

### Road Music과 원생 입력의 차이

| 항목 | 실제 적용 |
| --- | --- |
| `engine` | `yue`와 `yue-mlx`를 플랫폼·설치 상태로 구분. 사용자 지정 엔진 유지 |
| `style` / `parts` | 공통 조합을 거쳐 원생 `style`로 전달. `parts.genre`의 우선순위와 최종 전달본 확인 |
| `lyrics` | 공통 `cleanLyrics` 결과를 전달. ACE 워커의 4,096자 잘림을 YuE 한계로 사용하지 않음 |
| `bpm` / `parts.bpm` | Road Music은 40~220 입력을 받고 YuE에는 style의 BPM 문구로 전달. 정확한 템포 보장 아님 |
| `targetSeconds` | YuE 계열 20~360초의 유효 요청·목표 기록. 원생 SongRequest의 duration 제어가 아님 |
| `cot`, `abc`, `mode` | 계획 선택·제공 악보·계획 전용 생성은 아래 모드/공개 schema로 확인 |
| `advanced` | 공개 camelCase 키가 워커에서 원생 설정으로 매핑됨. 원생 `cfg_scale`, `semantic_sampling`, `generation_config`를 최상위 CLI 필드로 넣지 않음 |
| 커버·녹음 | 원생 YuE2의 score 기반 커버와 현재 Road Music의 `coverAudio`·`recording` 경로는 다름. 두 입력 경로는 현재 ACE용이며 YuE에 붙이지 않음 |

## 계획 모드와 ABC

| 목적 | `cot` | ABC |
| --- | --- | --- |
| 새 멜로디·화성·노래 | `full` 기본 출발점 | 미제공 시 모델이 계획 |
| 멜로디 계획과 자유로운 반주 | `melody` | 미제공 또는 검증한 코드 없는 멜로디 ABC |
| 악보 없는 직접 생성 | `off` | 제공 불가 |
| 화성·멜로디·형식 수정 | 보존 조건에 맞는 `full` / `melody` | 원본이 아닌 수정 사본 |

외부 ABC를 주면 planner를 우회한다. `cot:"melody"`가 입력 악보의 코드를 자동 제거하거나 잘못된 악보를 자동 보정하지 않는다. 네이티브 ABC는 `Vocal`·`Ins` 두 성부의 제한된 방언이다. 범용 ABC의 임의 다성 보표로 취급하지 말고 [공식 ABC 기준](vendor/yue2/official/skills/yue2-music/references/abc-editing.md)과 공개 `score:check`로 확인한다.

정확한 음악적 보존이 요청되면 원본 score·가사·style·tempo·seed를 비교 기준으로 남긴다. 음표·길이·마디·템포를 보존했는지와 실제 음원의 가창·음색·리듬이 같은지는 별도 검사다. 악보 계획 파일은 해시 검증되므로 원본을 제자리 수정하지 않는다.

## 길이·샘플링·입력 한계

YuE2의 원생 SongRequest에는 초 단위 길이 필드가 없다. `targetSeconds:180`이나 style의 3분 요청, ABC의 명목 길이가 실제 180초를 보장하지 않는다. EOS가 나오면 종료하며 토큰 상한에 걸리면 잘림 표시가 남는다. 목표에 맞추려고 사용자 가사를 줄이거나 오디오를 자르고 무음으로 채우지 않는다.

고정판 원생 기본값은 [protocol](vendor/yue2/official/src/yue2/protocol.py)과 [MLX usage](vendor/yue2/mlx/docs/usage.md)에 있다. ABC 최대 4,096·semantic 최대 9,000은 **토큰 예산**이며 가사 문자 수가 아니다. context 24,576에는 prefix와 생성 예산이 함께 들어간다. 초과를 임의 절단으로 해결하지 않는다. 코드·런타임·요청의 실효 설정을 기록하며 이 수치로 특정 길이·한국어 완창을 약속하지 않는다.

| 구분 | 근거와 사용 원칙 |
| --- | --- |
| 원생 semantic CFG | full/melody 1.0, off 1.01. ABC에는 CFG 없음. 워커의 실효 전달값은 별도 확인 |
| acoustic solver | 기본 midpoint 32단계. 단계 증가를 품질 향상 보장으로 안내하지 않음 |
| AR sampling | ABC/semantic의 기본값이 다름. [원문 표](vendor/yue2/mlx/docs/usage.md)의 해당 stage와 실제 전달본 비교 |
| Road Music 범위 | 원생 범위보다 좁을 수 있음. 예: 공개 seed는 최대 2,147,483,647, `advanced.cfgScale` 1~20, `odeSteps` 8~64. 최종 기준은 실행 `schema` |
| ACE와의 차이 | ACE Turbo의 CFG/8단계·caption 512자/가사 4,096자를 YuE의 제어·한계로 옮기지 않음 |

샘플링·CFG·양자화 비교는 요청된 범위에서 한 요소씩 바꾸고 실패 비용까지 기록한다. 기존 [2026-10-16 실험](model-production-guide.md)의 낮은 sampling/CFG 조정은 일반 권장값이 아니다. 모델 README의 best-of-N 평가를 1곡 요청의 다중 생성 권한이나 새 단일 음원의 품질 보장으로 해석하지 않는다.

## Road Music 입력 예시

아래는 **입력 형식용 짧은 예시**이며 3분 완성 가사가 아니다. 실제 제작은 요청한 전체 가사와 최종 정리·조합 결과를 검수하고 승인/위임 범위에서 제출한다. `title`·`engine`은 Road Music 필드이며, 원생 스킬의 `id`·`cfg_scale`를 그대로 넣지 않는다.

```json
{
  "title": "함께라서 좋아",
  "engine": "yue-mlx",
  "count": 1,
  "style": "Korean traditional trot, mature solo female vocal, clear Korean phrasing, two-beat ppongjjak rhythm, accordion, brass and drums, warm and affectionate",
  "lyrics": "[Verse]\n아침상을 마주 보고\n오늘 얘길 나눠요\n[Chorus]\n함께라서 좋아요\n당신이라 좋아요\n좋은 날도 궂은 날도\n우리 함께 걸어요",
  "bpm": 108,
  "targetSeconds": 180,
  "seed": 42,
  "cot": "full",
  "mode": "song"
}
```

Windows NVIDIA에서 같은 YuE2를 요청했다면 준비 상태에 맞게 `engine:"yue"`를 선택한다. MLX를 명시한 요청에서 몰래 바꾸지 않는다. 악기·BPM을 parts로 분리한다면 생성 JSON과 같은 값을 조합 검사에 사용한다. 최종 조합 결과를 다시 style에 넣어 같은 parts를 중복 조합하지 말고 검증한 원래 입력으로 생성한다.

```bash
node cli/road-music.js prompt:knowledge --json '{"topic":"yue"}'
```

생성에는 검증한 실제 파일을 `song:generate --file`로 전달하고 반환된 작업을 `job:wait`으로 확인한다. 이 문서 예시를 읽었다는 이유로 자동 제출하지 않는다.

## 수정·커버·연주곡

- **가사만 수정:** 요청한 구절·반복 위치만 보완하고 나머지 가사·style은 보존한다. [악보 선택](#score-choice)에서 가사 전달과 선율 보존 중 요청의 우선순위를 확인한다. 기존 ABC 재사용을 무조건 기본으로 삼지 않는다. 결과는 새 전체 녹음이며 수정 밖의 파형·가수 음색을 보장하지 않는다.
- **악보 수정:** 원본 계획 디렉터리는 보존하고 ABC 사본을 수정한다. 요청된 보존 항목과 지원 방언을 점검한 뒤 공개 score/render 경로로 새 버전을 만든다. 제목이나 템포·화성을 요청 범위 밖에서 바꾸지 않는다.
- **커버:** 공식 경로는 SheetSage2 전사 → 사람이 검토할 멜로디 ABC → chord 없는 melody 조건 생성이다. 전사 모델·원곡 권리·입력 파일이 필요하다. 현재 공개 Road Music에는 YuE용 직접 오디오 커버/가수 복제 필드가 없으므로 예시를 우회 실행하거나 새 전사 모델을 자동 설치하지 않는다.
- **연주곡:** 현재 Road Music은 `instrumental:true`를 지원한다. CUDA 워커는 Vocal 계획을 쉼표로 처리하고 MLX 워커는 포트의 `--instrumental`을 사용한다. 가사·후렴 검수는 해당 없음이며 제목만 해당 언어로 검수한다. 공식 main의 [Vocal→Ins 변환 스킬](vendor/yue2/current/skills/yue2-music/instrumental/SKILL.md)은 고정판 이후 별도 제작 절차다. 현재 워커의 처리와 동일하다고 설명하거나 모든 새 곡에서 그 스크립트를 실행하지 않는다. 두 경로 모두 실제 보컬 누출·선율 보존은 청취로 확인한다.

## 가사 수정 시 악보 선택

재제작 자체의 필요성은 [공통 효율 기준](music-review.md#retry-value)으로 먼저 판단한다. 한 음·받침·어미만의 교정은 [미세 발음 기준](music-review.md#micro-pronunciation)을 적용한다. 아래 표는 실행 가치가 있는 재제작의 악보 선택 기준이며, 비효율적 반복을 새 계획으로 바꿔 계속 권하는 근거가 아니다. 현재 `yue-mlx` 경로의 악보 수정은 새 전체 녹음이고 음절별 발음·다른 구간의 가창 고정을 보장하지 않는다.

가사 보존·악보 보존·음원 파형 보존은 서로 다른 조건이다. 같은 음절 수와 seed, 같은 ABC만으로 새 단어의 발음이나 가창 반영을 강제할 수 없다. 기존 가사의 틀에 맞추려고 승인된 새 가사를 임의로 줄이거나, 첫 후렴만 바꾸라는 요청을 뒤의 모든 후렴 변경으로 확대하지 않는다. 제목·다른 가사·프롬프트만 유지해 달라는 지시에서 기존 선율·ABC 고정 요구를 새로 추정하지 않는다. 이미 개사·재생성을 승인받았고 보존 조건과 충돌하지 않으면 악보 선택만으로 같은 입력의 재승인을 요구하지 않는다.

| 요청의 우선순위 | 선택과 확인 |
| --- | --- |
| 가사 전달·발음 보완이 우선이고 원곡 선율 고정 요구는 없음 | [효율 검토](music-review.md#retry-value)에서 재제작이 타당한 경우 수정 가사를 유지한 새 악보 생성을 우선 검토한다. `cot:"full"`, 외부 `abc` 미제공, 새 곡 출력 경로로 계획부터 실행한다. 기존 악보의 반복 불일치만으로 이 경로를 자동 권하지 않으며, 미세 발음 교정을 새 계획으로 우회하지 않는다. |
| 원곡 선율·악보 보존을 명시했거나 제공 ABC를 그대로 사용하라고 함 | 원 ABC와 새 가사의 호흡·음절 배치를 대조해 재사용한다. 국소 악보 수정은 허용 범위의 사본에만 적용한다. 새 악보 생성으로 선율 보존 요구를 조용히 대체하지 않는다. |
| 새 악보와 원곡 선율의 정확한 동일성을 함께 요구 | 새 계획으로 동일 선율을 보장할 수 없음을 설명하고 충돌하는 요구만 확인한다. 이미 받은 수정·생성 권한 전체를 다시 승인받지는 않는다. |
| 가사 변경 없는 기술적 재개 또는 제목·메타데이터 수정 | 재개는 같은 요청·해시·현재 시도 출처를 확인한다. 제목만 수정하는 작업에 새 악보·음원 생성이나 ASR를 추가하지 않는다. |

생성 전 제목·전체 가사·원래 style·최종 조합 style·seed·옵션의 보존 범위를 기록한다. 한 요소를 비교한다면 예를 들어 기존 요청에서 `abc`만 빼고 나머지는 유지한다. 새 악보 선택을 이유로 승인된 가사·프롬프트·다른 옵션을 함께 바꾸지 않는다. 선택은 기존 [승인·위임 범위](music-review.md#approval) 안에서 실행하며, 가사·악보 검토만 요청한 작업은 생성하지 않는다.

통합 생성의 새 계획 실행 여부는 실제 native 요청의 외부 ABC 부재, `plan.request.abc`의 null/미지정, planner 출력 토큰과 실행 로그, 외부 ABC prefix 사용 여부를 함께 확인한다. 계획·검토·렌더를 분리했다면 이 검사는 계획 단계에 적용하고, 렌더의 ABC가 그 새 계획에서 온 것인지 추적한다. 렌더 단계에 새 ABC가 제공됐다는 이유만으로 과거 곡의 악보 재사용으로 판정하지 않는다. 기존·새 score의 해시와 구조도 비교해 기록한다. **해시 차이는 결과 악보가 달라졌다는 증거이며 단독으로 새 계획 실행을 증명하지 않는다.** 반대로 같은 seed·입력으로 새로 계획한 악보가 같을 수도 있으므로 해시가 같다는 이유만으로 캐시 재사용으로 단정하지 않는다. 실패 복구에서 이번 수정 가사로 새로 만든 계획을 재사용하는 경우에도 과거 곡의 악보와 출처를 구분한다.

원 악보·기존 음원·실패 기록은 보존한다. 새 악보는 멜로디·화성·템포·길이와 가창을 바꿀 수 있고, 실제 시간·BPM은 프롬프트 요청값과 다를 수 있다. 이번 선택은 음악적 보존 범위를 바꾸는 것이므로 선율 고정 요구가 있으면 우선한다.

## MLX·재시도·산출물 검수

MLX는 원저자의 공식 CUDA 구현과 별도인 커뮤니티 포트다. Road Music은 AR 8bit·NAR BF16·32 midpoint 단계를 사용한다. 포트의 BF16 기본값, AR-only 8bit/4bit 선택, M3 Max 측정값과 Road Music M1 Ultra 관찰을 구분한다. 포트 문서는 양자화 변형의 맞대응 청취 검증을 미완료로 표시하므로 품질 동등성을 보장하지 않는다. 같은 seed라도 PyTorch/MLX의 난수·연산이 달라 같은 곡을 보장하지 않는다.

Mac의 설치·프로필·전원·메모리 조건은 [YuE2 Apple Silicon](yue-mlx.md)을 따른다. MLX 16GiB 프로세스 예산은 16GB Mac 지원이나 전체 메모리 하드 상한을 뜻하지 않는다. 메모리 압력·swap 보호 중단을 곧바로 실제 OOM으로 단정하거나 guard를 꺼서 재시도하지 않는다.

`song:resume`는 저장된 앱 요청을 재개 경로로 보낸다. MLX 원생 `--resume`는 완료된 matching request/config/weights와 해시를 확인해 **완성 결과를 재사용**하며, 중단된 AR/NAR를 정확히 이어 생성하는 기능이 아니다. 현재 워커는 불완전 attempt를 보존하고 새 attempt를 만들며, 검증된 완료 score를 새 요청의 ABC로 재사용할 수 있다. 바뀐 가사·style은 새 버전이지 동일 작업의 기술적 resume가 아니다.

완료 후 아래를 구분한다.

1. 실제 worker의 model/VAE·runtime revision, 요청/정리/전달 가사, style·cot·seed·실효 설정·출력 경로를 대조한다.
2. `result.json`의 상태와 **`truncated.abc`, `truncated.semantic`**를 각각 확인한다. 재생되는 파일이나 `status:complete`만으로 완곡이라고 판단하지 않는다.
3. 실제 길이·포맷·48kHz stereo·전체 디코딩, 끝맺음과 요청한 가사 누락·반복·발음을 검사한다. 목표와 실제 길이, 생성 본체·실패·복구 시간을 구분한다.
4. [전곡·구간 가사 반영 검수](#lyrics-verification)를 수행하고 기술 검사·자동 전사·직접 청취 판정을 나눠 보고한다. 청취하지 않았다면 여성 음색·꺾기·트로트 적합성·한국어 완창을 확인했다고 쓰지 않는다.
5. 원본 FLAC·악보·artifact와 새 버전을 보존한다. MP3는 별도 납품 변환이다. decoder만 비교할 때는 같은 latent를 재디코딩하며 가사·음악 변경과 섞지 않는다.

## 전곡·구간 가사 반영 검수

가사가 있는 YuE MLX 완성본·개사 재생성에 적용한다. 제목·가사 초안만의 언어 검수에는 음원이나 ASR를 요구하지 않는다. 연주곡의 가사 검수는 해당 없음이다. 가사 확인용 도구가 없으면 실행하지 않은 항목을 `확인 불가`로 남기며, 임의로 음성 모델을 설치하거나 음원을 외부로 전송하지 않는다.

1. **전달본과 원본 대조:** 먼저 [한국어 내용 검수](music-review.md#korean-review)와 음원 전달 판정을 구분한다. 어색한 가사를 정확히 전사했다고 내용까지 자연스러워진 것은 아니다. 승인된 제목·전체 가사·style과 준비본·실제 native 요청을 비교한다. 불일치가 있으면 전달·정리·잘림부터 조사한다. 입력이 맞는데 전사가 다르면 필요할 때 실제 조건 prefix를 읽어 수정 문구가 들어갔는지 확인하고, 이전 결과 재사용과 생성 모델의 조건 준수·ASR 오류를 구분한다. prefix에 문구가 있다는 사실은 정확히 가창했다는 증거가 아니다.
2. **파일 기술 검사:** `result.json`·두 truncation flag, 실제 길이·포맷·전체 디코딩을 확인한다. 새 악보/재사용의 실제 경로와 원본 보존도 별도로 확인한다. 재생 가능·작업 완료·악보 검사 통과만으로 가사 반영을 통과시키지 않는다. 가사가 있는 구간이 전사에서 누락되면 현재 악보의 해당 구간도 대조한다. 예를 들어 Intro/Outro의 Vocal이 모두 쉼표이거나 구간 자체가 없으면 계획과 가사 사이의 충돌 가능성을 기록한다. ASR만으로 실제 누락을 확정하거나 가사를 삭제해 맞추지 말고, 허용된 범위에서 이번 새 계획의 사본을 보완하거나 재계획한다. 명시한 선율·악보 보존 조건을 우선하며, 이를 바꾸는 보완·재계획은 해당 변경 권한 없이 실행하지 않는다. 음표 수를 음절 수와 맞춰도 정확한 가창이 보장되지는 않는다.
3. **전곡 무유도 전사:** 사용 가능한 로컬 ASR로 전체 음원을 전사한다. 가능하면 서로 다른 모델 두 개를 사용하되 같은 계열은 독립 청취 증거가 아님을 밝힌다. 하나만 있으면 단일 모델 검사라고 보고한다. 참고 가사·목표 구절을 ASR prompt/grammar에 주입한 결과를 무유도 검수로 제시하지 않는다. 태그·공백 등 비교에서 정규화한 항목을 기록하고 원문·원시 전사를 보관한다. 다른 후렴·절·마지막 구절까지 누락·치환·과잉 반복을 대조하며, 조사·어미·부정어를 없애거나 환각성 말미를 지워 일치율을 높이지 않는다.
4. **새 음원에서 목표 위치 찾기:** 전곡 전사·현재 악보 구간을 근거로 바꾼 구절과 요청 범위의 반복 위치를 찾는다. 새 악보라면 이전 음원의 시간대를 그대로 재사용하지 않는다. 원문과 전사를 구간별로 대응시키고 위치를 찾지 못하면 그 구간은 미확인으로 남긴다.
5. **문맥 있는 구간 재검수:** 목표 앞뒤를 포함한 약30초 문맥을 출발점으로 삼되 구절·악곡에 맞춰 조정하고 실제 추출 범위를 기록한다. 단어나 호흡 중간에서 자르지 않는다. 짧은 클립이 무관한 문장·자막·감사말을 내면 가창 실패로 단정하지 말고 문맥을 넓혀 같은 무유도 조건으로 재검사한다. 최초 실패·추가 전사·조건 변경도 함께 남긴다. 의미 있는 전사끼리 충돌하면 유리한 결과만 골라 통과시키지 않는다. 추가 검사로 새 판별 정보를 얻을 근거가 없으면 확인 불가·충돌 보존으로 검수를 마치며, 정답 전사를 찾기 위한 범위 탐색이나 재생성으로 이어 가지 않는다.
6. **구분해 판정·보고:** 아래 항목과 모델·명령·참고 가사 사용 여부·구간 시간·정규화 기준·잔여 불일치를 기록한다. 전체 문자 일치나 CER는 자동 전사 문자열의 비교이며 실제 가창 오류율·음질 점수가 아니다. 직접 청취가 가능한 경우 별도 확인하고, 도구로 듣지 못했으면 청취 미실행을 명시한다.

| 결과 항목 | 판정 근거 |
| --- | --- |
| 입력·보존 / 악보 생성·재사용 / 파일 기술 검사 | 각각 실제 요청·실행 로그·해시·디코딩 등으로 판정 |
| 자동 전사상 확인 | 전곡·문맥 구간의 사용 가능한 전사가 요청 문구를 뒷받침함. 판정 불가 전사와 단일 모델 한계도 별기 |
| 엇갈림·확인 필요 | 의미 있는 전사 간 불일치 또는 누락·치환 의심이 남음. 실제 오발음 확정과 구분 |
| 확인 불가 / 해당 없음 | 전사 실패·도구 미지원 / 연주곡 등 적용 대상 아님 |
| 직접 청취 | 실제 수행한 범위·근거와 판정. 미실행이면 발음·음색·음악적 완성도를 확인했다고 쓰지 않음 |

확인되지 않은 구절을 확정 오류로 취급해 범위 밖 가사를 개사하지 않는다. 불일치가 반복되면 전달본·계획 경로·모델/ASR 한계를 먼저 조사하고 [효율·중단·추천 기준](music-review.md#retry-value)을 적용한다. 목표 구절이 맞아도 기존 개선 구간이 흔들리면 전체 순이득을 비교하고, 새 근거 없이 같은 악보·단어 교체·새 ABC·CFG/seed 변경을 이어 추천하지 않는다. 더 안정적인 후보 보존과 미확인 판정이 최선일 수 있다. 추가 생성·재시도는 승인된 범위를 지키며, 실패나 확인 불가 결과도 보존한다.

### 2026-10-18 로컬 적용 사례의 범위

M1 Ultra64GB의 여성 트로트1곡에서 기존 ABC를 유지한 개사·CFG1.2/1.5 진단은 두 목표의 전사 일치를 확인하지 못했다. 이후 제목·전체 가사·style·seed·CFG1.5를 유지하고 외부 ABC만 제외한 full 생성은 새 악보를 만들었고, 전곡 두 ASR의 태그·공백 제외340문자가 일치했다. 첫 후렴·브리지도 전곡과30초 문맥 두 모델에서 확인됐다. 짧은 구간의 large 모델은 무관한 문장을 출력했으므로 그 실패를 숨기지 않고 판정 불가로 남겼다. 직접 청취는 미실행이다.

이는 새 악보 선택과 문맥 검수의 실용 근거인 **한 로컬 표본**이다. 기존 악보만이 이전 문제의 원인이었다거나 새 악보·30초 구간·CFG1.5가 모든 가창을 개선한다는 보장은 아니다. CFG1.5를 제작 기본값으로 승격하지 않는다.

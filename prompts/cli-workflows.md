# Road Music CLI 작업 프롬프트

[Road Music](../README.md) · [문서 지도](../docs/README.md) · [릴리스 노트](../releases/README.md)

이 파일은 자동 로드되지 않는다. 작업을 시작할 때 [AGENTS.md](../AGENTS.md), [CLI 설치](../docs/cli-install.md), [CLI 사용법](../docs/cli.md), [CLI 레퍼런스](../docs/cli-reference.md)를 먼저 읽은 AI 에이전트에게 아래 프롬프트 중 하나를 전달한다. 모든 경로는 사용자가 고른 실제 절대 경로로 바꾼다.

`RoadMusic-CLI-X.Y.Z`의 `X.Y.Z`는 설치한 CLI Release 버전이며 앱 버전과 다르다.

음악 제작 예시는 [장르별 프롬프트](../docs/genre-prompts.md), 상세 입력은 [음악 옵션](../docs/music-options.md), 최신 스타일 조사는 [리서치 프롬프트](../docs/music-research.md)를 참고한다. 이 파일은 설치·작업 실행·내보내기·진단에 집중한다.

생성 예시에도 [공통 검토 규칙](../docs/music-review.md)을 적용한다. 기본은 가사·프롬프트를 검증해 요청자에게 먼저 보여주며, 새 두 항목부터 생성까지 전부 자동 위임받은 경우에는 요청자 검토를 생략한다. 기존 승인안 실행과 명시한 수정·재생성은 공통 검토 규칙의 해당 범위를 따른다. 추가 재제작을 제안하기 전에는 [효율·중단·추천 기준](../docs/music-review.md#retry-value)으로 이전 시도와 전체 회귀를 판단하고, 순이득 없는 전곡 반복보다 가장 안정적인 후보와 현실적인 방법 하나를 권한다. 태그는 [구간 가이드](../docs/lyrics-tags.md)에 맞춰 쓴다.

ACE·YuE·`yue-mlx` 모두 **초안 → 제목·가사 검수 → 허용된 수정·재검수 → 대상 엔진의 기술 검증 → 기존 승인/위임에 따른 생성** 순서다. 한국어 제목 또는 가사가 있으면 [한국어 검수](../docs/music-review.md#korean-review)를 해당 항목에 적용하며 자동 위임도 생략하지 않는다. 한국어가 없으면 한국어 검수는 해당 없음이다. 별도 에이전트를 사용할 수 있으면 [검수 역할](ace-review.md)을 전달하고, 없으면 같은 기준으로 자체 검수한다. 연주곡은 제목만 검수하고 가사·후렴은 해당 없음으로 처리한다. 제목·가사 초안 검토만 요청한 작업에는 생성용 자료나 서비스 실행을 요구하지 않는다.

## 1. 설치와 환경 확인

```text
Road Music CLI 소스 키트에서 설치와 읽기 전용 환경 점검을 해줘.
키트 절대 경로: /사용자가 선택한 경로/RoadMusic-CLI-X.Y.Z
Node.js 버전을 확인하고 npm ci --include=dev로 CLI 의존성을 설치한 뒤 cli:version, cli:update:check, schema, app:state, setup:check, engines:list을 확인해줘. 음악 생성·모델 설치·기존 곡 삭제나 설정 변경은 하지 마. 새 CLI가 있으면 현재·최신 버전과 설치 대상만 알려주고, 업데이트·재설치는 요청으로 간주하지 마. 첫 상태 요청에서 서비스와 데이터 폴더가 초기화될 수 있다는 점은 보고해줘.
stdout 최종 JSON과 핵심 상태를 요약하고, 누락된 ffmpeg/ffprobe/ACE 엔진이 있으면 설치 명령을 실행하지 말고 알려줘.
```

입력은 키트의 절대 경로다. 출력은 설치 성공 여부, CLI 스키마 접근 여부, 환경·엔진의 읽기 전용 상태 보고다.

## 2. 10~30초 연주곡 두 곡 생성

```text
Road Music CLI로 서로 다른 10~30초 연주곡 두 곡을 생성해줘.
프로젝트 이름: CLI 연주 스케치
첫 곡: 15초, minimal warm piano, piano와 cello, 76 BPM.
둘째 곡: 25초, gentle acoustic guitar, acoustic guitar와 brushed drums, 96 BPM.
각 요청은 instrumental:true, engine:ace, 서로 다른 seed를 사용하고 --events --wait로 완료를 확인해줘.
시작 전에 app:state, engines:list, projects:list을 읽고 ACE가 준비되지 않았으면 설치·다운로드를 시작하지 말고 상태를 보고해줘.
성공하면 각 곡의 title, dir, audio, jobId를 반환해줘. 지정한 프로젝트를 만들거나 선택하는 변경은 허용하지만, 기존 곡을 수정하거나 기존 대기 작업을 제거하지 마.
```

입력은 위 음악 사양이며, 출력은 두 완료 곡의 실제 경로와 작업 결과다. 엔진 없음·연결 불명확 상태에서는 재제출하지 않는다.

## 3. 가사가 있는 보컬 곡 생성

```text
Road Music CLI로 아래 가사가 있는 30초 보컬 곡을 한 곡 생성해줘.
제목: 새벽의 길
스타일: warm Korean indie pop, intimate female vocal, piano and acoustic guitar, 90 BPM
가사:
[Verse]
새벽의 길을 천천히 걸어요
작은 불빛이 나를 비춰요
[Chorus]
오늘의 마음을 노래해요
다시 시작할 용기를 찾아요

시작 전에 app:state와 engines:list을 읽고, ACE 준비 상태를 확인해줘.
생성 전에 제목과 전체 가사를 한국어로 읽어 어색한 문장·용어·비유와 제목/후렴의 관계를 검수해줘. 제공한 원문은 임의로 고치지 말고, 문제가 있으면 위치·원문·수정안·이유·적용 여부를 제안으로 분리해줘. 제목·가사 판정과 독립/자체 검수 여부를 보고하고, lyrics:clean·lyrics:check·prompt:compose의 기술 검사와 구분해줘.
song:generate에는 engine:ace, targetSeconds:30, count:1을 사용하고 --events --wait로 결과를 확인해줘.
성공한 곡의 title, dir, audio, jobId와 실패 시 오류 JSON을 반환해줘. 모델 설치, 파일 삭제, 외부 전송은 하지 마.
```

입력은 제목·스타일·가사이며, 출력은 완료된 곡의 절대 경로 또는 검증 가능한 오류 JSON이다.

## 4. 앨범·SRT·MP4 내보내기

```text
Road Music CLI로 사용자가 고른 완료 곡만 내보내줘.
곡 폴더 절대 경로: /사용자가 선택한 경로/완료-곡-폴더
SRT 출력 절대 경로: /사용자가 선택한 경로/exports/완료-곡.srt
MP4 출력 절대 경로: /사용자가 선택한 경로/exports/완료-곡-영상.mp4
앨범 폴더 출력 절대 경로: /사용자가 선택한 경로/exports/앨범

먼저 songs:list과 song:detail로 곡 폴더가 현재 라이브러리의 완료 곡인지 확인해줘.
song:srt로 SRT를 만든 뒤 song:save-srt에 --output을 사용해 저장해줘.
선택한 곡만 담은 album:export를 MP3 형식으로 --output 앨범 폴더에 저장해줘.
video:render는 720p, 30fps, CPU, 배경 없음, 막대 스펙트럼, 한 번 재생으로 만들고 --output MP4 경로와 --events를 사용해 완료 응답을 확인해줘.
기존 출력 파일이 있으면 덮어쓰지 말고 충돌을 보고해줘. --overwrite, --confirm, 파일 삭제, 외부 전송은 사용하지 마.
```

입력은 사용자가 선택한 완료 곡과 세 출력 절대 경로다. 출력은 SRT·앨범 폴더·MP4의 실제 결과 경로와 작업 상태다.

## 5. 오류 진단

```text
Road Music CLI 오류를 읽기 전용으로 진단해줘.
실행한 명령: [사용자가 실제로 실행한 명령]
stdout JSON: [사용자가 받은 stdout 한 줄]
stderr 이벤트 또는 오류: [사용자가 받은 stderr 전체]
키트 절대 경로: /사용자가 선택한 경로/RoadMusic-CLI-X.Y.Z

app:state, service:status --no-start, setup:check, engines:list을 조회하고 필요한 경우 queue:list과 songs:list도 읽어줘.
오류 코드, 이미 실행됐을 가능성(uncertain:true), 다음의 비파괴적 확인 명령을 순서대로 제시해줘.
service:stop --confirm, 모델/곡 이동, 삭제, 재설치, 재생성, 외부 전송은 실행하지 마.
```

입력은 실제 명령과 JSON 로그다. 출력은 원인 후보, 근거, 다음 읽기 전용 확인 순서이며 자동 복구·재제출은 포함하지 않는다.

## 6. YuE MLX 가사 수정·재생성·완성본 검수

공용 [제작 스킬](../skills/road-music/SKILL.md), [악보 선택](../docs/yue-prompt-guide.md#score-choice), [전곡·구간 검수](../docs/yue-prompt-guide.md#lyrics-verification)를 적용한다. 기존 악보 재사용은 자동 기본값이 아니다. 선율 보존을 명시한 요청에는 아래 새 악보 예시를 그대로 적용하지 않는다.

```text
YuE MLX로 이미 승인한 수정 가사·프롬프트의 재제작 방법을 검토하고, 실행 가치가 있으면 승인 범위의 1곡을 재생성해 검수해줘.
원본 곡 dir: songs:list가 반환한 실제 절대 경로
승인된 수정 요청 JSON: 사용자가 고른 실제 절대 경로
이번에는 가사 전달이 우선이며 원곡 선율을 고정할 필요는 없어.

같은 곡의 이전 시도·전체 회귀·불확실성과 비용을 먼저 비교하고 지금 가장 나은 방법 하나를 추천해줘. 반복 재제작이 비효율적이면 안정적인 후보를 보존하고 그 이유·잔여 문제를 보고해줘. 이 예시에서는 그 경우 새 생성을 제출하지 마. 명확한 기술 원인의 수정과 한계를 알고 별도로 맡긴 한정 실험은 공통 기준에 따라 구분해줘. 아래 새 악보·생성 절차는 재제작이 타당한 경우에만 적용해줘.
한 음·특정 발음만의 미세 교정이라면 실제 지원 경로가 국소 수정인지 전곡 재생성인지 먼저 확인해줘. 한 음표·한 마디만 바꾼다는 사실을 새 해결 근거나 낮은 회귀 위험으로 취급하지 마.

제목·전체 가사·프롬프트와 유지하기로 한 옵션을 원본/승인안과 대조해줘.
전체 가사가 누가 누구에게 무엇을 말하는지, 절·후렴·브리지의 내용과 감정이 자연스럽게 이어지는지 별도로 검수하고 ASR 일치와 혼동하지 마.
기존 ABC는 제출하지 말고 cot:full로 새 악보부터 생성해줘. 가사에 맞추려고 승인 문장을 더 고치거나 다른 후렴을 통일하지 마.
기존 승인 범위에서 공개 song:generate로 제출하고 jobId를 job:wait으로 확인해줘.
새 악보 실행 로그·외부 ABC 미사용·planner 출력과 원/신규 score 해시·구조를 확인해줘. 해시만으로 새 계획이나 캐시를 단정하지 마. 가사 있는 구간이 전사에서 사라지면 현재 악보의 보컬 성부와 구간도 대조하고, 계획 충돌은 승인 범위의 사본 보완 또는 재계획으로 다뤄줘. 가사 자체를 삭제해 맞추지 마.
완성본의 전체 디코딩·실제 길이·잘림·입력 보존을 검사하고, 사용 가능한 로컬 ASR로 참고 가사를 주지 않은 전곡 전사를 대조해줘.
새 음원에서 수정 구절과 반복 위치의 시간을 찾아 문맥 있는 구간으로 재검수해줘. 짧은 구간이 불안정하면 약30초 문맥 등으로 넓혀 확인하고 최초 실패와 조건 변경도 남겨줘.
전체 입력 보존·악보 경로·파일 검사·자동 전사상 확인·직접 청취 여부를 나눠 보고해줘.
ASR가 없거나 결과가 엇갈리면 확인 불가/확인 필요로 명시하고, 실제 오발음으로 단정해 개사·추가 생성을 반복하지 마.
새 판별 정보가 없는 전사 반복은 끝내고, 안정 후보 유지와 남은 미확인을 권장안으로 보고하며 검수를 종료할 수 있어. 검수 종료를 전곡 발음 통과나 다음 생성 요청으로 해석하지 마.
기존 파일·실패 기록을 보존하고 설치·외부 전송·추가 후보 생성은 임의로 하지 마.
```

출력은 실제 음원·새 악보·전달 가사·설정과 항목별 검수 결과다. 별도 검수 에이전트에는 [완성본 검수 역할](ace-review.md)과 실제 근거를 전달한다. 새 요청에 맞춰 기존 악보 재사용을 선택했다면 그 이유와 보존 범위를 같은 결과에 남긴다.

기존 곡의 어색한 가사 자체를 전면 보완해 새 음원까지 만드는 요청은 [수정·생성 권한](../docs/music-review.md#approval)을 먼저 해석한다. 명시한 전체 개사는 원문 보존을 이유로 거부하지 않되, 가사만 다시 쓰라는 요청에는 생성을 추가하지 않는다. 현재 제목·주제와 기존 승인 스타일을 기준으로 새 가사를 검수하고, 변경 전후·이유·전곡 내용의 판단 근거를 보관한 뒤 허용된 재생성을 진행한다. 과거 제목·concept/hook이 남아 있어도 이를 되살리려고 현재 사용자 지시를 바꾸지 않는다.

# Road Music 음악 제작

CLI 키트에 동봉하는 작업 스킬이다. 기준 경로는 이 파일에서 두 단계 위의 키트 루트다. 프로젝트 [AGENTS.md](../../AGENTS.md)를 따르며, 문서 작성·설치만 요청된 작업에 음악 생성을 추가하지 않는다.

## 먼저 읽을 자료

- 공통: [검토·자동 생성 규칙](../../docs/music-review.md). 제목·가사의 표현만 검토할 때는 요청 범위의 원문 보존·한국어 검수 절을 읽으며, 생성용 자료나 CLI 조회를 요구하지 않는다.
- 가사 태그를 설계·검증할 때: [태그 사용법](../../docs/lyrics-tags.md). 연주곡은 가사 없음으로 처리한다.
- 새 가사를 맡았으면 [작사 설계](../../docs/music-review.md#songwriting-design), 외부 프롬프트 자료를 응용하면 [자료의 모델별 변환](../../docs/genre-prompts.md#external-adaptation)을 필요한 범위에서 읽는다. 자료의 출력 형식·Suno 전용 옵션을 현재 요청이나 ACE·YuE 기능으로 옮기지 않는다.

생성 입력을 준비할 때는 요청에 포함된 엔진의 행을 따라 해당 작업에 필요한 절만 읽는다. 여러 모델을 비교하는 요청은 각 모델의 자료를 읽되 공통 절차는 한 번 적용하고 입력·검증 결과는 모델별로 구분한다. 공식 자료에 있는 기능과 Road Music 공개 CLI 지원은 실행 버전 `schema`로 구분한다.

| 선택한 엔진 | 적용 가이드와 해당 작업의 원문 | 서로 옮겨 적용하지 않을 설정 |
| --- | --- | --- |
| ACE (`ace`) | [ACE 적용 가이드](../../docs/ace-prompt-guide.md)와 연결된 [고정 공식 원문](../../docs/vendor/ace-step-1.5/README.md) | 현재 Turbo 추론·caption/가사 한계는 ACE 경로에만 적용. YuE의 `cot`·ABC·고급 옵션은 ACE 옵션이 아님 |
| YuE2 Windows NVIDIA (`yue`) | [YuE 제작 가이드](../../docs/yue-prompt-guide.md)와 [고정 공식 YuE2 원문](../../docs/vendor/yue2/README.md)의 해당 절 | 초기 YuE-v1의 단계·프롬프트 규칙과 구분. ACE의 입력 한계·Turbo 옵션을 적용하지 않음 |
| YuE2 Apple Silicon (`yue-mlx`) | [YuE 제작 가이드](../../docs/yue-prompt-guide.md), [MLX 운영 안내](../../docs/yue-mlx.md), 필요한 기능의 [고정 MLX 원문](../../docs/vendor/yue2/mlx/docs/usage.md) | CUDA 설치·명령·메모리 수치를 Mac에 적용하지 않음. 목표 길이·자연 EOS·실제 길이·잘림을 구분 |

- 가이드 조회에는 `prompt:knowledge`의 `ace` 또는 `yue` topic을 사용한다. 미설치 상태·가이드 조회를 새 설치 권한으로 해석하지 않는다.
- 옵션·장르가 필요하면 [옵션](../../docs/music-options.md)과 [장르 레시피](../../docs/genre-prompts.md)의 해당 절만 읽는다. 최신 인기·플레이리스트가 언급되면 [리서치 절차](../../docs/music-research.md)를 따른다.
- 모델별 FLOW 조정·비교 요청에는 [모델별 제작·비교](../../docs/model-production-guide.md)를 읽는다. `models` topic은 실험 기록이며 제작 기본값이 아니다.

## 작업 흐름

1. CLI 호출이 필요한 작업에서 처음 연결한 세션이면 `cli:version`과 `cli:update:check`을 읽기 전용으로 한 번 실행한다. 새 CLI는 알리기만 하며, 음악 요청으로 설치·재설치·상시 감시를 시작하지 않는다. 사용자가 업데이트를 요청하거나 자동 업데이트를 명시적으로 위임할 때만 새 `cliPath`에 설치하고 버전·스키마·지식 조회를 확인한다.
2. 요청한 엔진·곡 수·언어·장르·보컬·길이를 파악한다. 엔진 지정은 해당 모델 가이드를 고르는 기준이며, YuE MLX 지정 요청을 ACE로 바꾸거나 미설치를 이유로 다운로드하지 않는다. **일반 “곡 만들어줘”는 기본 검토 모드다.** 새 가사와 프롬프트의 결정부터 생성까지 전부 자동 위임한 경우에는 요청자 검토를 생략한다. 기존 승인안의 실행과 명시한 수정·재생성은 [검토 규칙의 해당 범위](../../docs/music-review.md#preserve-input)를 따른다. 한쪽만 자동 위임했거나 “초안만” 요청했다면 생성하지 않는다. 이미 승인된 완성안을 그대로 생성하라는 요청은 재승인 없이 진행한다.
3. 가사가 있는 곡의 생성 입력에는 태그 가이드로 필요한 구간을 선택한다. 모든 태그를 억지로 넣지 않는다. 실제 부를 가사는 섹션 아래에, 보컬·편곡 지시는 style에 둔다. 연주곡은 가사·후렴 검수를 해당 없음으로 처리하며 가사 작성을 요구하지 않는다. `parts.structure`로 보컬 가사를 자동 구성한다고 가정하지 않는다. 빠진 취향은 합리적인 안으로 제안해 가정을 표시하고, 곡 수 미지정은 1곡으로 한다. 필수 원문·파일·권한이 없으면 해당 작업만 확인한다.
4. ACE·YuE·`yue-mlx` 모두 한국어 제목 또는 가사가 있으면 [한국어 검수](../../docs/music-review.md#korean-review)를 해당 한국어 항목에 수행한다. 한국어가 없으면 한국어 검수는 해당 없음이며 번역하거나 한국어 기준을 적용하지 않는다. 제목만의 자연스러움과 제공된 가사와의 관계, 어색한 문장·용어·비유, 반복 후렴까지 요청 범위에서 읽는다. AI 초안은 허용 범위에서 보완하고 다시 검수한다. 사용자 제공·승인 원문은 임의 수정하지 않으며 부분 수정은 지정 구절과 반복 위치로 한정한다. 제목·가사 판정과 수정 전후·이유·적용 여부·남은 문제를 기록한다. 자동 위임도 적용 대상의 검수를 생략하지 않는다.
5. 생성 준비에는 대상 엔진의 상태·schema·공개 입력 계약을 확인한다. 가사가 있으면 실제 경로의 `lyrics:clean` 전후와 `lyrics:check`를 대조한다. Road Music CLI의 ACE·YuE·`yue-mlx`는 모두 같은 스타일 조합을 거치므로 실제 생성과 같은 입력으로 `prompt:compose`의 notes·최종 style을 확인한다. 원문·입력 JSON·실제 전달본을 구분하고, 조합으로 승인된 의미가 달라지면 해당 부분만 보고·재검토하며 해결 전에는 생성에 제출하지 않는다. ACE 경로에서만 최종 caption 512자·정리 가사 4,096자 한계를 적용한다. 비교용 외부 런타임은 해당 입력 계약과 전달본을 확인한다. 정리·편집으로 한국어 전달본이 바뀌면 바뀐 부분과 문맥을 다시 검수한다. 지원되지 않는 필드를 추가하지 않는다. 제목·텍스트 초안 검토만 요청받으면 제공된 범위만 정적으로 점검하고, 도구 점검은 미실행으로 구분한다. 초안 검토를 위해 서비스를 시작하지 않는다.
6. 생성까지 요청된 기본 검토는 **최종 제목·완성 가사·한국어 검수 결과(해당 없음 포함)·최종 caption·입력 JSON·기술 검증 결과·출처**를 한 번에 보여주고 응답을 기다린다. 승인 전 생성 제출은 하지 않는다. 자동 위임은 질문으로 멈추지 않고 적용 대상의 언어 검수·기술 검증 후 요청 범위에서 생성한다.
7. 기존 곡의 추가 후보·재제작은 제출 전에 [효율과 최선의 방법 추천](../../docs/music-review.md#retry-value)으로 이전 시도·회귀·비용과 지원 기능을 판단한다. 순이득 없는 반복은 권하지 않고 가장 안정적인 후보와 현실적인 방법 하나를 먼저 추천한다. 명확한 기술 원인의 수정과 사용자가 한계를 알고 명시한 한정 실험은 구분한다. 이미 승인된 동일한 실행 범위에 재승인을 요구하지 않으며, 그 승인을 후속 후보·새 실험으로 확대하지 않는다. 실행하기로 한 승인/위임 범위의 JSON으로 제출하고 완료를 확인한다. 이후 음악·최종 제목·실제 가사·한국어 검수 결과·caption·설정·seed·참고 자료·선택 이유·검증 한계를 제공한다. 비교에는 목표와 실제 길이, 생성 본체와 실패·복구 시간, 실제 로드한 모델을 구분한다. ASR 전사 일치도를 실제 가창·청취 점수로 바꾸지 않는다. 승인 후 의미가 달라지는 AI의 수정은 재검토받되, 사용자가 구체적 수정과 생성을 함께 요청했다면 그 지시를 따른다.

전체 가사 재제작은 [전곡 내용 검수](../../docs/music-review.md#korean-review)로 주제·화자/대상·정서 흐름을 확인한다. 가사가 자연스러운지와 ASR가 입력을 그대로 전사했는지는 별도 판정이며, 명시한 전체 개사·재생성 권한과 부분 수정·초안만 요청을 구분한다.

YuE MLX 가사 수정·재생성은 [효율·미세 발음 교정 판단](../../docs/music-review.md#micro-pronunciation)을 먼저 적용하고, 재제작 자체가 타당한 경우에만 [악보 선택](../../docs/yue-prompt-guide.md#score-choice)으로 진행한다. 그 범위에서 가사 전달이 우선이고 선율 고정 요구가 없으면 새 악보를 우선 검토하며, 기존 ABC를 무조건 재사용하지 않는다. 명시한 선율·제공 악보 보존은 우선하고 제목·나머지 가사·프롬프트는 승인 범위대로 유지한다.

YuE MLX 완성본은 [전곡·구간 검수](../../docs/yue-prompt-guide.md#lyrics-verification)에 따라 입력·악보 경로·파일 기술 검사, 전체 및 문맥 구간의 무유도 전사, 실제 청취 여부를 나눠 보고한다. 새 악보의 구간 시간은 새 음원에서 찾고, 불안정한 짧은 전사는 문맥을 넓혀 확인하되 실패 기록도 보존한다. 도구가 없으면 미확인으로 밝히며, 단일 성공 사례의 CFG·구간 길이를 보편적 기본값으로 만들지 않는다.

태그 의미와 실제 처리의 차이는 태그 가이드, 승인 범위·부분 위임·수정·재시도는 검토 문서가 기준이다. 별도 에이전트가 있으면 [검수 역할](../../prompts/ace-review.md)로 요청 범위의 제목·가사 또는 가사 없음·입력과 근거를 독립 점검한다. 검수 에이전트의 판단은 요청자의 승인을 대신하지 않으며, 에이전트가 없으면 작성 후 별도 단계에서 적용 대상의 언어 검수와 기술 점검을 직접 수행하고 자체 검수라고 밝힌다. 도구·에이전트가 없는 기능을 수행했다고 주장하지 않는다.


## 음악 생성 뒤 HTML 모션그래픽 연결

사용자가 **음악과 HTML 모션그래픽 제작을 함께 요청했을 때만** 적용한다. 음악만 요청한 경우에는 이 단계를 추가하지 않는다.

1. `song:generate` 뒤 `job:wait`으로 완료를 확인한다. `--wait`을 사용했어도 각 완료 결과의 성공·실패를 읽는다.
2. `songs:list`으로 완료 목록을 다시 읽고, 완료 응답과 목록에 있는 실제 절대 `dir`·`audio` 경로를 그대로 사용한다. 제목으로 경로를 추측하거나 원곡 파일을 이동·변경하지 않는다.
3. 비어 있는 새 절대 출력 폴더를 정해 `motion:handoff --json '{"music":"완료 응답의 audio 절대 경로","out":"새 프로젝트 절대 경로","mode":"..."}'`를 호출한다. 결과의 `nextCommand`를 그대로 이어 `motion:studio`를 연다.
4. HTML 제작실에서 사용자가 선택·업로드·청취를 마친 뒤 반환된 `selection`, `request`, CD/Showreel의 `showreel-request.json`을 읽는다. 선택한 모드의 동봉 `SKILL.md`와 [모션그래픽 연결 가이드](../../docs/cli-motion-graphics.md)를 따라 이미지·자막·영상 작업을 진행한다. 선택 값을 임의로 교체하지 않는다.
5. 음악 없이 화면 구성부터 요청받은 경우에는 `music`을 생략해 프로젝트를 만들고 HTML에서 파일을 업로드한다. CD/Showreel 생성 단계에서는 실제 음악 입력이 준비된 뒤에만 `plan/create --selection`을 진행한다.
